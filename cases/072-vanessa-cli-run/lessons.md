# Уроки

**Симптомы и причины.**
- «Клиент тестирования не подключен» на первом шаге интерфейса — в сценарии нет шага подключения. Первым шагом: `Дано Я открыл новый сеанс TestClient или подключил уже существующий` (клиент — из `КлиентыТестирования` параметров).
- Лог прогона пустой («Start … Закрытие клиента тестирования») при статусе 0 — шаги в лог не пишутся без `ВыводитьВЛогВыполнениеШагов`; итог сверять с JUnit (`tests`, `failures`) и с данными базы (COM-запрос), а не с одним статусом.
- Менеджер после падения остаётся открытым, следующий запуск упирается в занятый порт — перед и после прогона закрывать клиенты тестовой базы (по пути базы в командной строке процесса).
- Формулировки шагов — только из библиотеки VA: регистрации `ДобавитьШагВМассивТестов(ВсеТесты, …)` в `features/Libraries/*/step_definitions/**/Module.bsl` (часть — с префиксом `Ванесса.`), частые — `VanessaAutomation/Templates/ЧастоИспользуемыеШаги`. Модель «помнит» похожие, но несуществующие.
- «Не ноль» для числа — `поле с именем 'X' заполнено`; «содержит» — `стал равен шаблону "*текст*"`.

- Видео: окно клиента 1С в перечислении окон (EnumWindows) не находится по заголовку — `1cv8.exe` лишь запускатель, окно у дочернего `1cv8c.exe`, заголовок появляется не сразу; кириллица в тексте `-Command` PowerShell 5.1 искажается. Надёжно: ждать процесс с `/TESTCLIENT` и писать весь рабочий стол (`gdigrab -i desktop`), клиент выводить вперёд шагом «я активизирую главное окно сеанса TESTCLIENT».

**Что изменилось.** `tools/vanessa.py` — сборка `VAParams.json` из `platform.json` (`va_epf`, `va_port`), запуск, закрытие клиентов тестовой базы, разбор JUnit и лога, код возврата; образец — `reference/testing-ui/eam_defect_order.feature`.

**Правило.** Разведка формы — `platform.py ui` (шаг `дамп`: имена элементов); постоянный сценарий — `.feature` для Vanessa с шагами по именам элементов (`ИскатьЭлементыФормыПоИмени`). Зелёный прогон подтверждать данными (документы созданы и проведены).
