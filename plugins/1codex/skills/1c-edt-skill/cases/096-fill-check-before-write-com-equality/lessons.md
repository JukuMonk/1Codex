# Уроки

**Проверка заполнения идёт раньше `ПередЗаписью`.** Интерактивная запись: `ПроверитьЗаполнение` (стандартная
проверка + `ОбработкаПроверкиЗаполнения`) → `ПередЗаписью`. Реквизит с проверкой «Выдавать ошибку», который собирается
в `ПередЗаписью`, не даёт записать новый объект. Собирать его в `ОбработкаПроверкиЗаполнения` — и продублировать в
`ПередЗаписью` для программной записи (обработки, COM проверку заполнения не вызывают). Лучше всего — показывать
сразу в форме при изменении исходных полей.

**COM-тест не воспроизводит интерактивную запись.** `Объект.Записать()` через COM минует проверку заполнения — тест
ДиЗ-03 «наименование по шаблону» проходил при неработающей форме. Для поведения формы: в COM-тесте явно
`Объект.ПроверитьЗаполнение()` перед `Записать()`, а форму — нажатиями.

**Через COM ссылки и значения перечислений — разные объекты:** Python `==` всегда `False`. Сравнивать
`cn.XMLString(а) == cn.XMLString(б)`. Строку неограниченной длины в запросе — ПОДОБНО, не «=»; `ТекущаяДата` через COM
недоступна — параметр `datetime.now()`.

**Генератор после «принять выгрузку»** не должен переписывать целиком созданные им объекты (`enum_xml`,
`catalog_xml`) — иначе сверка снова находит расхождения: создавать, только если файла нет.

**Строка 2000 символов → неограниченная** (case 024: больше 1024 — «Слишком большое значение описателя длины» при
обновлении БД). Заказчику — пометка в отчёте.
