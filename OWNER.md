# Как выпускать обновления 1Codex

Исходники находятся в main. Push и pull request запускают Validate 1Codex:
автономные тесты, структуру Designer, линт, ссылки, каталог и старую песочницу
на Windows и Linux. Они не публикуют новую версию коллегам.

После просмотра отчёта и решения владельца выполнить Publish stable 1Codex plugin
через workflow_dispatch: source_ref — проверенный коммит, version — новая
версия вида 1.1.0. Workflow фиксирует SHA, повторяет проверки на обеих ОС,
собирает пакет из этого же SHA и обновляет прежнюю ветку plugin. Коллегам
не требуется менять адрес marketplace. Их ежедневное обновление получает
только явно выпущенные версии.

Выпуск из грязного checkout запрещён. Для локальной проверки без публикации:

```
python packaging/build_plugin.py --include-worktree --version 1.1.0 --output <outside-repo>
```

Такой пакет отмечен review_build и worktree_dirty, содержит хеши исходных файлов
и полный отчёт selftest. Он не считается опубликованной стабильной версией.

Откат: выбрать предыдущий исправный исходный коммит и выпустить его содержимое
под НОВЫМ номером исправления. Повторить приёмку и обновление на чистом профиле.
Не переписывать историю ветки plugin и не подменять файлы уже установленного
пакета вручную. Список изменений — docs/CHANGELOG.md.

Windows updater хранит update.log и status.json. Ключ -StatusOnly читает состояние
без сетевых действий. Обновление самого updater требует повторного запуска
нового установщика; schema_version помогает выявить старую установку.
Задача остаётся ежедневной и при входе пользователя; после получения новой
версии начать новый чат. Проверки платформы 1С выполняются отдельно в песочнице:
GitHub CI не располагает вашей платформой и лицензией.

Порядок выпуска введён в 1.1.0. Локальные изменения workflow начинают
действовать на GitHub только после их публикации в репозиторий.
