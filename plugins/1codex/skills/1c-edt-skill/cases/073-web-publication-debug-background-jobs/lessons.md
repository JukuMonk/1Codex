# Уроки

**Как искать.** «Пустой результат» у ВСЕХ отчётов только в веб-клиенте и падающий фоновый расчёт — проблема не отчётов, а фоновых заданий публикации. Сначала сделать так, чтобы ошибка фонового задания была видна (статус `ДлительныеОперацииКлиент.ОжидатьЗавершение` ≠ «Выполнено» → `КраткоеПредставлениеОшибки` показать пользователю), потом читать её, а не гадать.

**Причины, которые проверять по порядку.**
1. `default.vrd`: `<debug enable="true" … url=""/>` — «Ошибка регистрации предмета отладки в отладчике» в каждом фоновом задании. Выключить отладку или указать адрес работающего `dbgs`.
2. Лицензии: у файловой базы через веб-сервер каждому фоновому заданию нужна своя лицензия; при их нехватке — «Не обнаружено свободной лицензии!» (версия «для разработчиков» ограничена по сеансам).
3. Права пользователя веб-сервера на каталог базы; несколько рабочих процессов веб-сервера (Linux prefork/worker: результат во временном хранилище другого процесса).
Быстрая проверка без правок: `…/ru_RU/?C=РежимОтладки` — БСП выполняет длительные операции без фонового задания; заработало — дело в фоновых заданиях.

**Код.** В клиентском коде, который должен работать в веб-клиенте, не использовать `ЗаписьJSON`/`ЗаписатьJSON`: собирать литерал вручную или сериализовать на сервере. Иначе ошибка оформления вывода маскирует исходную ошибку.

**Правило.** После публикации на веб-сервере — открыть отчёт и начальную страницу в веб-клиенте (не только в тонком); `default.vrd` проверять на `<debug enable="true">`.
