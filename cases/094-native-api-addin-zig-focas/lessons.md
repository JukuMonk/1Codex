# Уроки

**Компонента Native API без Visual Studio — zig.** `pip install --user ziglang` (без прав администратора) →
`python -m ziglang c++ -target x86_64-windows-gnu -std=c++17 -O2 -shared -D_WINDOWS …` и
`-target x86_64-linux-gnu.2.17 -fPIC -fvisibility=hidden … -ldl -lpthread` с одной машины; libc++ статически, zip
~900 КБ. Образец сборки и упаковки — `after/сборка_zig.py` (MANIFEST.XML + обе библиотеки).

**ABI: деструктор в vtable.** Платформа под Windows — MSVC: `virtual ~X()` = ОДНА ячейка (scalar deleting dtor).
Clang/MinGW (Itanium) — ДВЕ (complete + deleting). Без поправки 1С вызывает «соседний» метод (`Init` → деструктор,
`AllocMemory` → не то). Поправка — `after/include/addin_abi.h`: в заголовках 1С `virtual ~IInitDoneBase() {}` и т. п.
заменены макросом: под Windows не-MSVC у БАЗОВОГО интерфейса — заглушка в одну ячейку
(`virtual void __stdcall msvc_dtor_slot_X(unsigned) {}`), у ПРОИЗВОДНОГО (`IComponentBase`, `IAddInDefBaseEx`) —
ничего (в MSVC его деструктор переопределяет ячейку базового, новой не добавляет — иначе съедет `GetInterface`).
Свой класс компоненты — без виртуального деструктора; `DestroyObject` удаляет через конкретный тип. Под Linux
(платформа — gcc, тот же Itanium) деструкторы как в оригинале. Заголовки Native API — из примера 1С (ИТС).

**Строки.** `WCHAR_T` — 2 байта и под Windows (`wchar_t`), и под Linux (`uint16_t`); `basic_string<uint16_t>` в libc++
нет `char_traits` → `std::u16string` с приведением к `WCHAR_T*`. Возвращаемые строки — только через `IMemoryManager`
(`AllocMemory`), имена методов и свойств — тоже. `FindMethod`/`FindProp` — без учёта регистра, с кириллицей и Ё.

**Подключение.** По ПУТИ К ФАЙЛУ `ПодключитьВнешнююКомпоненту` берёт только саму .dll/.so; zip с MANIFEST.XML —
только из макета (`"ОбщийМакет.Имя"`) или временного хранилища
(`ПоместитьВоВременноеХранилище(Новый ДвоичныеДанные(Путь))`). Общий макет без EDT: `<TemplateType>AddIn</TemplateType>`,
данные — `Ext/Template.bin` (zip как есть); `designer_lib.common_template_xml(имя, kind='AddIn')`; сверка обратной
выгрузки — побайтно (текстом .bin не читается). Через COM (внешнее соединение) компонента грузится в процесс Python
— удобно для тестов.

**Компонента — только связь, логика — в BSL.** Методы `ЗагрузитьБиблиотеку(Путь)` (библиотека производителя
динамически: `LoadLibraryExW(…, LOAD_WITH_ALTERED_SEARCH_PATH)` / `dlopen`, в поставку не входит), `ДобавитьСтанок`,
`ПрочитатьВсе() → JSON`, `Пауза(Мс)` (в 8.3.21 у языка нет «спать» — цикл регламентного задания ждёт ей). Все станки —
своими потоками внутри одного вызова (`std::thread` + join), у каждого свой срок; исключения наружу не выпускать
(падение компоненты роняет процесс сервера 1С). Регламентное задание раз в минуту крутит внутри цикл с интервалом
константы — образец `after/Module_ОпросЧПУ.bsl` (`ВыполнитьЦикл`).

**FOCAS.** Дескриптор (`cnc_allclibhndl3` … `cnc_freelibhndl`) — на один опрос и в одном потоке: у ЧПУ мало сетевых
сессий, незакрытый при обрыве дескриптор их съедает. Структуры (`after/focas.h`) — с `#pragma pack(4)` и `int32_t`
вместо `long` (под Linux x64 `long` = 8 байт — известная беда libfwlib32). Подставная библиотека
(`after/fwlib_подставная.cpp`) — те же экспорты, сценарий из текстового файла (рядом с DLL или env), перечитывается
на каждом вызове: тест меняет «станок» на ходу (пуск/стоп, нет связи с задержкой, «нет функции» EW_FUNC). Она
собрана по ТОМУ ЖЕ заголовку — ошибку раскладки не покажет: сверить с `fwlib32.h` на первом реальном станке.

**Тест из Python через ctypes:** у каждой функции `restype = ctypes.c_short` — иначе отрицательные коды FOCAS
приходят мусором в старших битах.

**Двоичный сигнал в классификаторе состояний.** Запись «на сейчас» + даты до секунды → считать состояние до
`Момент + 1`; пороги для 1/2 — с гистерезисом (вход 1,5 > выход 1,4), иначе «не откалибровано». Нет связи — нет
записей → OFFLINE по таймауту, не OFF.

**Среда (Git Bash).** Кириллица в имени файла, созданного из bash, теряется при передаче Python — временные скрипты
называть латиницей; скрипты правки — файлом (Write), не heredoc'ом; пути для Windows-Python — `C:/…`, не `/c/…`.
