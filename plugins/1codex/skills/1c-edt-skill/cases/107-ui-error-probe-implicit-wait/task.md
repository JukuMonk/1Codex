# Диагностика UI замедлила каждый шаг теста

Проект: UP, оптимизация инструментов UI, 30.10.2026.
Платформа: 8.5.1.1529, управляемый файловый клиент, TestManager/TestClient.
Confidence: HIGH для измеренного сценария; перенос на 8.3 и серверные базы не проверен.

Менеджер проверял наличие ErrorInfo перед и после каждого шага. Для этого он
обходил открытые окна и вызывал НайтиОбъект по двум типам элемента. При отсутствии
ErrorInfo каждый поиск неявно ожидал его появления. Действия стали занимать около
12 секунд вместо долей секунды, хотя никакой ошибки в приложении не было.

После замены поиска на чтение существующего дерева только активного окна
проверены положительные сценарии и отрицательные сценарии отсутствующей кнопки
и исключения UI_OPT_EXPECTED_RUNTIME. Проверены точный текст ошибки и диагностика
без ожидания очередного 60-секундного таймаута формы. Сама проверка ошибки
занимала примерно 20–40 мс на тестовой форме.

Сопоставимые строки журналов одного стенда:

| Шаг | До | После |
|---|---:|---:|
| скопировать-строку | 11996 мс | 330 мс |
| ожидание уже открытой тестовой формы | 17833 мс | 24 мс |

Это замеры конкретных прогонов, а не универсальная оценка RPC или таймаута API.
При оформлении кейса новые сеансы 1С не запускались; использованы журналы
положительного и отрицательных прогонов проекта.
