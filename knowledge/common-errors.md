# Каталог ошибок

### Регистр накопления: FillValue не входит в Resource / Dimension
- Общий построитель поля вызван без `fill=False`. Для XML Конфигуратора —
  `designer_lib.accumulation_register_xml`; кейс 099. Загрузка может вернуть 0:
  читать журнал и сверять обратную выгрузку.

### Повторное проведение через тот же COM-объект удваивает остаток
- Перед формированием движений очищать набор записей, а не табличную часть
  документа: кейс 100. Проверять два проведения подряд, отмену и новое проведение.

Только то, что реально случилось в проекте-источнике (коммиты — в
`cases/`). Формат: симптом → причина → неправильно → правильно → как
проверить → case. Confidence HIGH, если не сказано иначе.

## EDT не видит объект / объект не загружается

### Объект есть на диске, а в дереве EDT / конфигурации его нет
- Причина: нет строки в `Configuration.mdo`.
- Неправильно: создать `src/DataProcessors/X/X.mdo` и ждать.
- Правильно: `<dataProcessors>DataProcessor.X</dataProcessors>` последней в группе.
- Проверить: `tools/check_project.py` («не прописан в Configuration.mdo»).
- Case 021.

### «Ошибка добавления объекта … нельзя добавлять объекты метаданных без загрузки родительского объекта»
- Причина 1: новый объект (обработка, отчёт, роль, модуль, подсистема) при
  ИНКРЕМЕНТАЛЬНОМ обновлении базы.
- Причина 2: дочерняя подсистема без `<parentSubsystem>`.
- Причина 3: частичная загрузка (`LoadConfigFromFiles -listFile`) новых объектов без корня — или корень без
  корневых `Ext/**` (`ParentConfigurations` у типовой на поддержке). Корень переносить целиком. Case 091.
- Правильно: полное обновление конфигурации ИБ один раз; `parentSubsystem`
  у каждой дочерней; устойчивые uuid.
- Проверить: `check_project` (parentSubsystem); в EDT — полное обновление.
- Cases 019, 020.

### «Файл объекта не существует …/Subsystems/X.xml» при полном импорте
- Причина: подсистема без `parentSubsystem` — её нет в модели.
- Case 019.

### «Ошибка SDBL: слишком большое значение описателя длины» при обновлении базы
- Причина: строковый реквизит длиннее 1024.
- Правильно: `Строка(0)` (неограниченная).
- Проверить: `check_project` / `check_mdo`.
- Case 024.

### «Свойство Use / FillFromFillingValue / FillValue не входит в состав объекта метаданных Attribute» (формат Конфигуратора)
- Причина: состав свойств реквизита зависит от владельца (справочник / ТЧ /
  документ); в EDT-аналоге у реквизита ТЧ нет `fillValue`.
- Case 025.

### «NullPointerException … "formItem" is null» при обновлении базы из EDT
- Причина: генератор переписал форму, открытую в редакторе EDT; файлы целы,
  сломана модель рабочего пространства.
- Правильно: «Проект → Очистить…»; закрывать редакторы перед генерацией.
- Проверить: `1cedtcli export` в чистое рабочее пространство проходит.
- Case 028.

### «Неверный путь к данным "Список.Description"» (и `Список.Ref`) по КАЖДОМУ полю списка при загрузке базы
- Причина: платформа не скомпилировала произвольный запрос динамического списка: `ИЗ` чужой таблицы (форма скопирована
  из БСП), `ССЫЛКА` на тип, которого нет в определяемом типе. EDT validate молчит, инкрементальная загрузка неизменённую
  форму не перепроверяет.
- Правильно: в запросе списка — свой объект в `ИЗ`, невозможная `ССЫЛКА` → `ЛОЖЬ`.
- Проверить: загрузка в ПУСТУЮ базу (`tools/platform.py load`).
- Case 063.

## Форма не открывается / пустой лист в EDT

### Редактор EDT показывает пустой лист вместо формы (XML валиден)
- Причины (каждая ловилась отдельно): числовой реквизит без
  `numberQualifiers` (001); нет `saveWindowSettings` (002); номера колонок
  таблицы совпали с номерами реквизитов (003); таблица без спутников
  `searchStringAddition/viewStatusAddition/searchControlAddition` (004).
- Как найти: лесенка проб — формы, отличающиеся на один элемент (006).
- Проверить: `check_form`.

### Маршрутный лист УАТ открывается вопросом «Требуется конвертация данных документа в формат "Релиз 1.1.21"» / в тест-клиенте форма пустая
- Причина: лист записан своим кодом с `ОбменДанными.Загрузка = Истина` — типовой `ПередЗаписью` не вызвал `РассчитатьСтатусДокумента`, `Статус` пуст; форма в `ПриОткрытии` спрашивает о конвертации.
- Правильно: перед записью в режиме обмена `Документы.уатМаршрутныйЛист.РассчитатьСтатусДокумента(Объект)`; записанным — дозаполнить. В тест-клиенте признак — `ИмяАктивнойФормы: ErrorWindow`, текст окна — снимком каждого окна процесса. Case 089.

### Мобильная форма не открывается ни в EDT, ни в платформе
- Причина: у корня конфигурации нет `<usePurposes>MobileDevice`.
- Case 005.

### «Неверный путь к данным» при открытии формы в платформе
- Причина: `<segments>` ведёт к реквизиту, которого нет на форме (три поля
  сразу).
- Проверить: `check_form` (корень пути ∈ реквизитам).
- `knowledge/managed-forms.md` §5.

### Форма открылась, но «всё разъехалось»: поля строки по колонкам всей страницы
- Причина: у группы нет `showLeftMargin/united/throughAlign/currentRowUse` —
  сквозное выравнивание «Использовать».
- Case 007.

### Поле тянется до края формы, соседи уехали вправо
- Причина: `width` без `autoMaxWidth=true`.
- Case 008.

### Панель полей наверху, пустота, таблица прижата к низу
- Причина: группе в вертикальной колонке не задан `verticalStretch=false`.
- Case 009.

### Поле HTML: белый экран при живой странице
- Причина: нет `width`/`height` у поля — viewport нулевой высоты.
- Case 022.

### Поле HTML: пустая страница, «Поле обмена in_… не найдено»
- Причина: макет в LF (одна строка), строки длиннее допустимого, нет полей обмена.
- Case 023.

### Форма списка открылась, но без панели пользовательских настроек / отбор пользователя не виден
- Причина: нет группы `…КомпоновщикНастроекПользовательскиеНастройки` перед таблицей или ссылки
  `userSettingsGroup` в `DynamicListTableExtInfo`.
- Правильно: скелет `examples/forms/list-form/`, `edt_lib.dynamic_list_table`.
- Case 038 (MEDIUM).

### Иконка раздела / команды мыльная
- Причина: в `Picture.zip` один PNG. Нужны 8 масштабов (`85.png` … `400.png`), `Picture.png` и `manifest.xml` с BOM.
- Правильно: `edt_lib.picture_manifest`. Case 040 (MEDIUM).

### Начальная страница пустая / нужной формы на ней нет, а в `Configuration.mdo` свойства не найти
- Причина: состав начальной страницы — отдельный файл `Configuration/HomePageWorkArea.hpwa`; пустой `<visibility/>`
  у формы = «скрыта для всех»; настройка пользователя сильнее умолчания.
- Правильно: `<visibility><common>true</common></visibility>` (`edt_lib.add_form_to_home_page`). Case 061.

## Команда есть, но не работает / обработчик не вызывается

### «Процедура или функция с указанным именем не определена (ОткрытьФорму)» при нажатии кнопки
- Причина: процедура модуля формы без директивы → серверная.
- Case 011.

### «… не определена (ТочкаМаршрута)» при открытии, функция на месте
- Причина: вставка кода между директивой и объявлением — функция потеряла
  `&НаСервереБезКонтекста`.
- Case 012.

### «{ОбщийМодуль.X.Модуль(N,M)}: … не определена (ЧислоИлиНоль)»
- Причина: функция из чужого модуля вызвана без префикса; общий модуль
  проверяется только при выполнении.
- Case 013.

### «… не определена (мвмИерархияПоОтбору)» у процедуры `&НаКлиентеНаСервере`
- Причина не доказана; лечение — две процедуры (MEDIUM).
- Case 033.

### «Поле объекта недоступно для записи (Параметры)»
- Причина: переменная названа именем свойства формы.
- Case 010.

### 8.5: при выделении нескольких строк кнопок своих команд над таблицей нет
- Причина: выделение включает системную панель множественного выделения; команда формы попадает туда, только если у неё «Использование выделенных строк» = Использует И задана «Используемая таблица» (`SelectedRowsUse` в XML — мало).
- Правильно: в `ПриСозданииНаСервере` `Команды.X.ИспользуемаяТаблица = Элементы.Т`, `Команды.X.ИспользованиеВыделенныхСтрок = ИспользованиеВыделенныхСтрок.Использует`; строки — `Элементы.Т.ПолучитьСтрокиДляОбработки()`; подбор флажками — родное выделение, без колонки «Пометка». Case 085.

### Кнопка в мобильном клиенте спрятана в «ещё», в таблице «More actions»
- Причина: команды в панели; командная панель таблицы.
- Case 041.

### `ПараметрыВыбора` с отбором заданы, а форма выбора открывается без отбора
- Причина: типовая открывает форму выбора сама (`…НачалоВыбора`) и параметры выбора элемента не читает.
- Правильно: в начале типового `НачалоВыбора` — свой вызов: `СтандартнаяОбработка = Ложь`, открыть форму с `Отбор`
  и `ТекущаяСтрока` и оповещением о завершении; в форме выбора читать `Параметры.Отбор` в `ПриСозданииНаСервере`.
- Case 036.

## Ошибка клиент/сервер и платформы в бою

### «Значение не является значением объектного типа (ЗначениеКопирования)» при открытии формы по навигационной ссылке
- Причина: ссылка построена от ПУСТОЙ ссылки (`ПолучитьНавигационнуюСсылку` от пустого значения, например строка с незаполненным документом) — форма открывается как новый объект с параметром копирования.
- Правильно: отбирать `<> ЗНАЧЕНИЕ(….ПустаяСсылка)` и `НЕ ПометкаУдаления`. Case 089.

### Веб-клиент: отчёты «Не удалось сформировать отчет (пустой результат)», фоновый расчёт падает
- В `default.vrd` публикации `<debug enable="true" url=""/>` — «Ошибка регистрации предмета отладки в отладчике» в фоновом сеансе; выключить отладку, перезапустить веб-сервер. Case 073.

### Веб-клиент: «Процедура или функция с указанным именем не определена (ЗаписатьJSON)» / «(XMLСтрока)»
- `ЗаписьJSON`/`ЗаписатьJSON` и `XMLСтрока` на клиенте в веб-клиенте недоступны (в тонком — есть: снимки и COM не
  ловят) — литерал вручную, дата `Формат(Дата, "ДФ=yyyy-MM-dd") + "T00:00:00"`, сериализация на сервере. Что видел
  пользователь — `ВыгрузитьЖурналРегистрации` через COM, уровень «Ошибка» (`cases/084-…/after/журнал_ошибок.py`). Кейсы 073, 084.
### Веб-клиент: «Процедура или функция с указанным именем не определена (ЗаписатьJSON)»
- `ЗаписьJSON`/`ЗаписатьJSON` на клиенте в веб-клиенте недоступны — литерал вручную или на сервере. Case 073.
- Тонкий клиент падает при закрытии формы (`mngui.dll`, `0xc0000005`), EDT молчит — повтор имени элемента формы (группа и поле `Проект`). Case 086.
- Наименование на форме узкое, а поле с `width` растянуто в горизонтальной группе — `field(stretch=True/False)`, таблица `max_width=False`. Case 087.
- «Несоответствие типов (параметр номер '4')» в `НачатьПомещениеФайлов` при нажатии кнопки загрузки — после диалога нужен булев «Интерактивно»: `(Оповещение, , Диалог, Истина, УникальныйИдентификатор)`. Case 088.

### «Поле объекта не обнаружено (ОбменДаннымиЗагрузка)»
- Правильно `Объект.ОбменДанными.Загрузка`. Case 014.

### «Поле объекта не обнаружено (ПустаяСсылка)»
- Правильно `ПустаяСсылка()`. Case 032.

### «Поле объекта не обнаружено (Запрет)» — значение перечисления
- Имя значения из `.mdo`. Case 045.

### Кэш/регистр «находит» запись, которой нет
- `Получить` независимого регистра возвращает структуру всегда; читать
  запросом. Case 018.

### «Строка, не закрывающаяся кавычкой» — падает сборка всего пакета
- Одиночная кавычка в тексте запроса; пустая строка — `""""`. Case 015.

### «Ожидается имя» в запросе
- Псевдоним/реквизит — ключевое слово (`По`). Case 016.

### «Преобразование значения к типу Число не может быть выполнено» на чистой базе
- Группа иерархического справочника в запросе (NULL). Case 017.

### «Неверные параметры МАКСИМУМ»
- Агрегат по строке неограниченной длины; `ВЫРАЗИТЬ … КАК СТРОКА(150)`. Case 031.

### «Ожидается выражение "ВЫБРАТЬ"» — весь пакет запросов не выполняется
- Два `;` подряд после выброса запроса. Case 046.

### «Поле объекта не обнаружено (ТС)» при чтении результата пакета
- Индекс `Результаты[N]` сдвинулся после вставки запроса в середину. Case 042.

### «Ожидается символ ';'» после вставки в типовую процедуру
- Последний оператор типовой процедуры без `;`. Case 026.

### Форма пустая / данные не пришли, ошибка одна строчка в окне сообщений
- Необязательный расчёт внутри сборки данных не в `Попытка`. Case 043.

### «Процедура или функция с указанным именем уже определена (Состояние)» — толстый клиент
- Причина: имя функции серверного модуля совпало с глобальным методом; профилировщик EDT
  запускает толстый клиент.
- Правильно: переименовать; `check_bsl` (GLOBAL_METHODS). Case 047.

### «Ожидается имя процедуры» при открытии формы
- Причина: команда формы названа ключевым словом (`Прервать`). Case 057.

### «Преобразование значения к типу Число не может быть выполнено» на первой строке данных
- Причина: `Число + "строка"` — тип задаёт левый операнд. Case 058.

### «Нельзя изменять поле, содержащее объект данных формы»
- Причина: локальная переменная с именем реквизита формы в процедуре с контекстом. Case 059.

### «Переменная не определена (X)» в процедуре БезКонтекста
- Причина: обращение к реквизиту формы там, где формы нет. Case 060.

### Кэш модуля с повторным использованием «не работает»
- Причина: несуществующее значение `returnValuesReuse` (`DuringCall`) принято EDT молча. Case 048.

### Операция идёт секунды и минуты при «небольших» данных
- Причина: перебор O(N²), загрузка данных на каждый вызов, реквизит через точку в цикле,
  запись всех объектов пакета, геометрия «каждый с каждым», отбор без индекса.
- Правильно: профиль с целью «Сервер», затем cases 049, 050 (реквизит через точку в цикле), 051 (запись всех
  объектов пакета), 052 (геометрия без описывающего прямоугольника), 053, 055 по строкам профиля.

### «Неоднозначное поле "X.Ссылка"» при открытии отчёта или запроса
- Причина: псевдоним таблицы (обычно подзапроса) совпал с именем табличной части объекта запроса. Case 062.

### «Запись с такими ключевыми полями существует» при проведении второго документа на тот же ключ
- Регистр, подчинённый регистратору, уникален по измерениям во всём регистре; признак документа, по которому «последний перекрывает», должен быть измерением. Case 064.

### «Поле не найдено "…Код"» / «…ЭтоГруппа»; «Ожидается …» на псевдониме `В`
- Нет кода (`codeLength` 0), нет групп, псевдоним — ключевое слово. Case 065 (и 016, 017).

### «Не задано значение параметра …» в отчёте СКД
- Параметр в запросе без `{}` — `use=Always` и значение по умолчанию. Case 068.

### «Переменная не определена (СпособКодированияСтроки)» при щелчке в поле HTML
- Параметры ссылок страницы — hex, раскодирование своей функцией. Case 069.

### Объект, который пользователь только что завёл, молча исчез после записи (транзакция зафиксирована)
- Причина: запись пропустила объект (`Продолжить`), а следующий шаг «пометить лишние» снял всё, чего нет в списке
  записанных; или табличную часть перезаписали пустым результатом разбора.
- Правильно: каждый `Продолжить` кладёт объект в оставшиеся с причиной; пустой разбор — ТЧ не трогать (`НечегоПисать`).
- Case 044.

- «Тип не определен (ТестируемоеПриложение)» у тестируемого клиента — тип есть только в `/TESTMANAGER`; `Новый("ТестируемоеПриложение", Параметры)` (071).
- «Метод объекта не обнаружен» у тестируемого поля/формы — имена из `test.dll`: `reference/testing-ui/test_api_8.5.1.md` (071).
- «В элементе управления отсутствует указанное значение» — выбирать `ОтображаемыйТекст` строки подсказки целиком (071).
- «Неподходящий тип / состояние элемента управления» — поле только для чтения; ячейка редактируемой строки без ухода из неё (071).
- Vanessa: «Клиент тестирования не подключен» — первый шаг «Дано Я открыл новый сеанс TestClient или подключил уже существующий» (072).

## Без EDT: выгрузка Конфигуратора и внешние обработки

### «Неизвестное имя типа - CatalogRef.<объект расширения>» при сборке .epf
- Причина: при `LoadExternalDataProcessorOrReportFromFiles` типы расширений не известны.
- Правильно: в метаданных `.epf` — `cfg:AnyRef`; объекты расширения — только в коде.
- Case 074; `knowledge/designer-format.md` §2.

### Собранная .epf без методов модуля объекта (COM: «AttributeError <unknown>.Метод»)
- Причина: `ObjectModule.bsl` не в `<Имя>/Ext/` (внутри папки объекта); сборка всё равно код 0.
- Case 074; `knowledge/designer-format.md` §3.

### «Исключение XDTO произошло при чтении файла …/Forms/…/Ext/Form.xml» при загрузке расширения
- Причина: выгрузка расширения 8.3.27 (заимствованные формы) не загружается обратно даже без правок, и частично тоже.
- Правильно: проверить конкретную выгрузку на копии; для нового инструмента возможна внешняя обработка. Это ограничение кейса 074, а не всех расширений: сгенерированное расширение описано в кейсе 081.
- Case 074.

### «Неопознанный оператор» на ровном месте
- Причина 1: переменная с именем ключевого слова языка (`И`, `ИЛИ`, `НЕ`).
- Причина 2: метод у выражения `Новый Тип(...)` (`Новый Файл(П).Существует()`).
- Case 074.

### «Поле объекта недоступно для записи (Окно)» в модуле формы
- Причина: `Окно` — свойство формы; локальная переменная с этим именем = присваивание свойству.
- Правильно: другое имя (`ОкноКлиента`). Cases 010, 074.

### Таблица формы пустая, а счётчик/заголовок («Изменения (1)») верный — в тестовом клиенте
- Причина: вкладка, впервые показанная шагом `ТестируемаяГруппаФормы.Активизировать()` после возврата из другого окна, не отрисовывает строки (данные есть).
- Правильно: не чинить код по фантому; проверить переключением вкладки из формы (`Элементы.Страницы.ТекущаяСтраница`) — так и сделать в форме, если вкладку надо показать.
- Case 075.

### Страница поля HTML «висит» на заглушке, а поле ошибок пустое
- Причина: ошибка разбора основного скрипта гасит и его `window.onerror`; `--dump-dom` не видит `value`, выставленное из JS.
- Правильно: ранний отдельный `<script>` с `onerror`, состояние — в `textContent` обычного элемента. Case 075.


### ECharts в поле HTML: `Cannot set properties of null (setting 'innerHTML')` после щелчка
- Причина: перерисовка `setOption(…, true)` (notMerge) прямо в обработчике `click` — подсказка пересоздаётся, её отложенный показ пишет в удалённый элемент.
- Правильно: `setTimeout` после обработчика и `setOption(опции, {replaceMerge: ['series']})`. Case 076.

### Библиотека в поле HTML: `getRootNode is not a function`, `structuredClone`, `matchAll is not a function`
- Причина: WebKit поля HTML 1С 8.3.27 этих функций не знает (Edge знает — в браузере всё работает).
- Правильно: замены в раннем скрипте до библиотек; перед встраиванием прогнать по библиотеке поиск современных API. Case 076.

### Headless Edge молча пуст (код 0) — запуск из Bash-инструмента
- Причина: из Git Bash на Windows Server `msedge --headless --dump-dom/--screenshot` ничего не выводит даже для about:blank.
- Правильно: проверки страниц запускать из PowerShell. Case 076.


### Веб-клиент: «Сеанс отсутствует или удален» сразу после входа
- Причина: процесс веб-сервера упал (Apache: `child process exited with status 3221225477`). Модуль 8.5.1 на базе ТОИР 3.0 (8.3.27) — сбой в компоненте СЛК `licenceaddin` (журнал приложений Windows).
- Правильно: веб-модуль той же версии, что база; при чужой версии в рабочем Apache — отдельный экземпляр (служба, свой порт). Case 077.

### Зарегистрированная дополнительная обработка нигде не видна
- Причина: в базе (копии) выключена функциональная опция `ИспользоватьДополнительныеОтчетыИОбработки`.
- Правильно: включить константу; в ТОИР команда — в разделе («Дополнительные обработки»), не на начальной странице. Case 077.

### Опубликованная файловая база: регламентные задания не идут / Конфигуратор не загружает конфигурацию
- Причина: задания файловой базы выполняет процесс веб-сервера только после первого сеанса с его запуска; тот же процесс держит базу, пока жив сеанс.
- Неправильно: искать в default.vrd атрибут `allowexecutescheduledjobs` (его нет; `/AllowExecuteScheduledJobs` — ключ клиента).
- Правильно: после запуска Apache — короткий вход тонким клиентом `/WS"http://<сервер>/<имя>"`; на время загрузки конфигурации и копирования базы Apache останавливать. Case 077 (дополнение ZHDRM).


### «Поле "Наименование" не заполнено», хотя ПередЗаписью его составляет
- Причина: стандартная проверка заполнения идёт ДО записи.
- Правильно: в ОбработкаПроверкиЗаполнения при пустом наименовании убрать его из ПроверяемыеРеквизиты. Case 078.

### `cn.Формат(...)` / `cn.Строка(...)` / `cn.ТекущаяДата()` через COM — AttributeError; `НайтиПоНомеру` вернул пустую ссылку
- Причина: у COM-соединения этих глобальных функций нет (есть `String`, `XMLString`, `XMLValue`); номер документа уникален в пределах периода (`numberPeriodicity`), а дата интервала не передана.
- Правильно: дату — `cn.XMLString(д)` и срез строки; документ по номеру — запросом `ГДЕ Номер = &Н УПОРЯДОЧИТЬ ПО Дата УБЫВ` или `НайтиПоНомеру(Номер, Дата)`; серверные процедуры формы — шагом Vanessa. Case 090.

### Дата через COM записалась на 3 часа раньше; `cn.Тип(...)` — AttributeError
- Причина: pywin32 переводит «наивный» datetime из местного пояса в UTC; глобального `Тип()` через COM нет.
- Правильно: `XMLЗначение(NewObject("ОписаниеТипов", "Дата").Типы().Get(0), "ГГГГ-ММ-ДДTЧЧ:ММ:СС")`. Case 078.

### Регламентное задание «каждые 20 с» идёт раз в минуту (файловая база)
- Причина: в файловой базе задания выполняет клиент, с шагом около 60 с; первый запуск — через ~2 мин после старта клиента.
- Правильно: частое обновление — обработчиком ожидания формы или серверная база. Case 078.

### Менеджер UI-тестов молча стоит, журнала нет
- Причина: «Предупреждение безопасности» при `/Execute` внешней обработки; в базе без пользователей его не отключить.
- Правильно: тестовая копия с пользователем, у которого `ПредупреждатьОбОпасныхДействиях = Ложь`; запуск с `/N`. Case 078.


### «Необходима версия платформы не ниже 8.5.1» при загрузке .dt
- Причина: выгрузка базы 8.5.1 (заголовок `1CIBDmpF3`) загружается платформой 8.3.x.
- Правильно: `CREATEINFOBASE` и `/RestoreIB` платформой 8.5.1+; файлы выгрузки такой базы — `version="2.21"`, генератору — `designer_lib.VERSION = '2.21'`. Case 080.

### Нужны данные базы, а COM — «Внешнее соединение не разрешено», `/Execute` ждёт «Предупреждения безопасности»
- Причина: у роли снято право «Внешнее соединение»; внешняя обработка требует подтверждения защиты от опасных действий.
- Правильно: обработка в конфигурации локальной копии, `/URL "e1cib/app/Обработка.<Имя>"`, работа в `ПриСозданииНаСервере`, `ЗавершитьРаботуСистемы(Ложь)` в `ПриОткрытии`; универсальная выгрузка в JSON — `cases/080-…/after/`. Case 080.

### «Добавление дочерних объектов этого типа к заимствованным в расширениях недопустимо в режиме совместимости 8.3.2x и ниже»
- Причина: в заимствованный регистр нельзя добавить измерение, ресурс и даже реквизит при совместимости ≤ 8.3.25; режим расширения не выше основной конфигурации.
- Правильно: свой регистр-спутник (те же измерения + поля доработки), запись `&После` метода движений, чтение левым соединением. Case 081.

### «Текущее ChildObjects, ожидаемое CommonForm» / «свойство ThisNode типа InternalInfo отсутствует» / «Неизвестная команда …StandardCommand.Open» при загрузке расширения
- Причина: общая форма — не контейнер; у плана обмена в InternalInfo нужен `xr:ThisNode`; командный интерфейс заимствованной подсистемы ссылается на незаимствованные объекты.
- Правильно: `<CommonForm>` без `ChildObjects`; новый `xr:ThisNode`; в командном интерфейсе — только команды объектов расширения. Case 081.

### «Не удалось обновить права ролей конфигурации … Найдены подключенные расширения конфигурации, изменяющие роли конфигурации»
- Причина: БСП обновляет `ПраваРолей` только в сеансе без расширений, меняющих роли (обновление ИБ через COM).
- Правильно: выключить расширение → `ВыполнитьОбновлениеИнформационнойБазы()` → включить; `Записать()` расширения через COM — с `ЗащитаОтОпасныхДействий` без предупреждений. Case 081.

### «Записи регистра сведений стали неуникальными» после загрузки поставки вместо доработанной конфигурации
- Причина: ушло измерение доработки — записи с разными его значениями совпали по ключу; заодно молча удаляются колонки и таблицы доработок.
- Правильно: до замены — выгрузка данных доработок и удаление «лишних» записей, после подключения расширения — загрузка (`cases/082-…/after/migrate.py`). Case 082.

### Через COM: `Connect.ТипЗнч`, `Connect.XDTOСериализатор` — AttributeError; `Метаданные.X[имя]` — «does not support enumeration»
- Причина: у внешнего соединения нет части глобального контекста; часть свойств доступна только по английскому имени; коллекции метаданных не индексируются строкой.
- Правильно: `cn.XDTOSerializer`, `cn.XMLTypeAssignment`; тип параметра СКД — из `Схема.Параметры[i].ТипЗначения`; `Метаданные.X.Найти(имя)`. Case 082.

### «Поле объекта не обнаружено (<объект>)» в `…ОбновлениеИнформационнойБазы` при обновлении типовой через несколько релизов
- Причина: обработчик старой версии в коде новой ссылается на объект, позже переименованный поставщиком («Удалить…»).
- Правильно: обновлять через промежуточный релиз; иначе временное расширение-исправление на время обновления ИБ (`cases/083-…/after/update_fix_ext.py`). Case 083.

### «Поле объекта не обнаружено (КлючПредопределенногоВарианта)» — отчёт БСП через COM
- Причина: модуль отчёта читает ключ варианта из доп. свойств настроек, их заполняет форма.
- Правильно: `Настройки.ДополнительныеСвойства.Вставить("КлючПредопределенногоВарианта", Схема.ВариантыНастроек[0].Имя)`. Case 083.

### `/CheckModules`: «Функция <<?>>ИмяПользователя()»; «не определена (Ln)»
- Своя функция с именем глобального метода (`ИмяПользователя`, ср. `Состояние`, `Сообщить`); натурального `Ln` в языке
  нет — `Log(x)`, `Exp(x)`, `Log10(x)`. Case 084.

### Развёрнутая .dt демо-базы через час показывает «Не настроено» / «нет данных» у всего оборудования
- Причина: данные заложены вперёд, а регистры, которые база досчитывает «до текущего момента» (состояния, итоги),
  посчитаны только до момента выгрузки.
- Правильно: перед `/DumpIB` досчитать их до конца заложенного периода явно (расчёт с параметром «момент»); формы
  показа брать «сейчас» из интервалов, обмен по расписанию выключить; проверить разворачиванием. Case 084.

### `/RestoreIB` в новую базу: «Пользователь ИБ не идентифицирован»; `CREATEINFOBASE` — код 1 без лога
- В пустой базе пользователей нет — `/N`/`/P` не передавать; строку соединения `File="…"` передавать СТРОКОЙ команды
  (shell), не списком аргументов. `cases/084-…/after/dt_выгрузка.py`. Case 084.

### Git Bash: после `sed -i` в diff «изменён весь файл»
- `sed -i` переводит CRLF выгрузки в LF. Правка готовых файлов — Python-скриптом из файла (`newline=''`, тот же перевод
  строк, счёт вхождений); скрипт с `'''` в heredoc команды может сорвать её разбор. Case 084.

### «Исключение XDTO» на всю форму / «OpenByValue» отвергнут при загрузке выгрузки Конфигуратора
- Неверное имя `StdPicture.*` в форме — XDTO-исключение всей формы; `…StandardCommand.OpenByValue.<Измерение>` у
  непериодического регистра загрузка не принимает; у справочника нет `ExtendedPresentation` в `Forms/<Имя>.xml`.
- Интерфейс конфигурации (разделы, начальная страница, SVG-картинки) — файлы `Ext/`, `Configuration.xml` их не
  упоминает (`designer_lib`). Case 079.

### Внешняя компонента (clang/MinGW, zig) в 1С под Windows падает или вызывает «не тот» метод
- Платформа — MSVC: виртуальный деструктор интерфейса — 1 ячейка vtable, у Itanium ABI (MinGW) — 2; методы Native API съезжают. → `cases/094-…/after/include/addin_abi.h`: у базовых интерфейсов заглушка в одну ячейку, у производных — ничего; удаление — через конкретный тип. Case 094.

### `ПодключитьВнешнююКомпоненту(<путь к .zip>)` → Ложь, «Тип не определен (AddIn.…)»
- По пути к файлу — только сама .dll/.so; архив с MANIFEST.XML — из общего макета (`TemplateType` `AddIn`, `Ext/Template.bin`) или временного хранилища. Case 094.

## Генераторы и правка XML

### После сохранения формы в EDT вывод генератора расходится с файлом на каждом поле
- Причина: EDT пишет теги в своём порядке (`<title>` за `<id>`, `<handlers>` за `</dataPath>`) и не пишет умолчаний.
- Правильно: генератор пишет так же (единый образец поля); правки пользователя в EDT переносить в спецификацию
  генератора, цель — разница 0 строк. Case 027.

### Ссылка на форму по умолчанию в `.mdo` встала не туда / EDT переписывает файл
- Причина: место `defaultObjectForm`/`defaultRecordForm`/`defaultListForm`/`defaultChoiceForm` зависит от вида
  объекта (у регистра `dataLockControlMode` после ссылок, у справочника — до).
- Правильно: `edt_lib.add_form_to_mdo`. Case 039 (MEDIUM).

### Второй прогон генератора вставил правки дважды
- Причина: проверка «уже применено» `стало in текст and было not in текст` ложна, когда `стало` начинается с `было`.
- Правильно: проверять только `стало in текст`; прогон дважды подряд — второй печатает «уже». Case 056 (и 012).

### После запуска одного генератора в проекте «пропали» обёртки модулей и раскладка форм
- Причина: поздние этапы цепочки дорабатывают файлы, которые ранние пишут целиком.
- Правильно: в проект — всегда вся цепочка (`build_all.py`), затем git diff только намеренных файлов. Case 070.

## Постановка и правка типовой

### «Группа» в ТЗ, а сделали иерархию справочника
- Иерархия меняет структуру, запросы (`ЭтоГруппа`) и формы; «Группа: реквизит, тип — Справочник X» — это реквизит.
  Неясно — уточнить у автора ТЗ. Case 029.

### Элементы типовой формы скрыли правкой XML — упрощение не отключить, обновление поставки конфликтует
- Правильно: XML типовой не трогать (только свои элементы); скрытие и перенос групп — в модуле под константой, вызов
  и в конце типовой `УстановитьВидимость`; свои умолчания — ПОСЛЕ типовых. Case 037.

## Различия desktop / mobile

- Смахивания по строке нет — только по страницам (030).
- Булевы колонки показываются «No»; командная панель таблицы — «More
  actions»; кнопки панели — в «ещё» (041).
- Одна форма с двумя назначениями работает в обоих клиентах; страницы
  `TabsOnTop` видны и на телефоне (006, 030).
- **UI-тест «медленный» только со снимками** (шаг после снимка 70–244 с): PrintWindow тормозит клиент — снимать копией экрана (`ImageGrab` по окну PID). Case 092.
- **Снимки UI — чужое окно или «screen grab failed»:** копия экрана снимает то, что сверху, а при свёрнутом/отключённом RDP рабочий стол не рисуется вовсе. Проверять видимость окна (`WindowFromPoint`), иначе пропускать снимок; PrintWindow тормозит клиент. Case 092.
- **Правило «не делать X» нарушается снова:** превратить в PreToolUse-хук (`tools/hook_heredoc.py` — heredoc с обратной косой). Case 092.
- **Начальная страница `OneColumn`: «Текущее LeftColumn, ожидаемое Column»** — элементы в `<Column>`; **команда `Representation` PictureAndText — исключение XDTO** — у команд `TextPicture`. Case 095.
- **Тест-клиент: флажок «Неподходящий тип элемента управления»** — `УстановитьОтметку()` без параметров. Case 095.
- **«Поле «Наименование» не заполнено», хотя наименование собирается при записи** — `ОбработкаПроверкиЗаполнения` идёт раньше `ПередЗаписью`: собирать в обоих. Case 096.
- **COM-тест: сравнение ссылок / перечислений всегда ложь** — `cn.XMLString(а) == cn.XMLString(б)`. Case 096.
- **Открыть отчёт СКД с параметром:** пустые `НастройкиКомпоновкиДанных` — параметра нет («Параметр с указанным именем не найден»); `ФиксированныеНастройки` перекрываются сохранёнными пользовательскими; `Параметры.X` формы вне `ПриСозданииНаСервере` — «Поле объекта не обнаружено (X)». Работает: параметр формы → реквизит при создании → при открытии установить в пользовательских настройках и `ПараметрыДанных`, `СкомпоноватьРезультат`. Проект UP, ЛОВУШКИ У-31.
- **Текст ошибки модального окна в UI-тесте не виден** — шаг «дамп»: декорация `ErrorInfo` содержит полный текст.
- **«Заполнить всеми строками» подтягивает только часть** — ключ повторяется в самом источнике (реквизит в шапке и в табличных частях), а защита от повтора проверяет «ключ уже есть»: вторую строку отбрасывает то же заполнение. Защита — по количеству (сколько раз ключ был до заполнения), ключ — с табличной частью. Case 098.
- **«Поле объекта не обнаружено (Имя)» при нажатии кнопки формы, открытой с параметром** — `Параметры.Имя` прочитан в процедуре `&НаКлиенте`: не ключевой параметр формы доступен только в `ПриСозданииНаСервере` (ключевой, `<KeyParameter>true`, — всегда). Сохранить в реквизит формы при создании. Ловит `tools/lint_dump.py` (`designer_lib.check_form_params`) до загрузки. Проект UP, 19.10.2026.
