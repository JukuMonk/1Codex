# Уроки

**PrintWindow тормозит тестируемый клиент 1С.** Окну посылается запрос отрисовки (`WM_PRINT`/`PW_RENDERFULLCONTENT`), и
следующая загрузка динамического списка в этом клиенте идёт десятки секунд (замер UP 8.5.1: 70–244 с вместо 0,3–0,9 с).
Снимать копией экрана — `PIL.ImageGrab.grab(bbox=прямоугольник главного окна процесса)` (BitBlt с экрана, окну ничего
не посылается), предварительно `SetForegroundWindow`. Условие — видимый, не свёрнутый сеанс; чёрный кадр
(`getbbox() is None`) считать неудачей и падать на PrintWindow. Снимок 1,8 → 0,4 с, сценарий ДиЗ 279 → 12 с.
Если тест «медленный» только со снимками — подозревать инструмент, а не форму.

**Один сценарий — один клиент.** Дробление на части стоит запуска/закрытия клиента, сборки менеджера и отдельного
таймаута на каждую часть. Ожидание считать от числа шагов (40 с × шагов, минимум 300 с), менеджер пересобирать только
если его исходники новее `.epf`, журнал опрашивать каждые 0,2 с. Обзор 176 шагов: ~1700 с → 110 с, ошибок 0.

**Длительность каждого шага — в журнал.** Без `[N мс]` у строк «медленная форма» и «медленный инструмент» неотличимы;
с ними причина нашлась за один прогон.

**Ошибки текста запроса — до платформы.** `designer_lib.check_query(text)` (псевдоним после КАК — ключевое слово,
непарные кавычки) перед COM-запросом и перед записью формы списка; линт проекта (модули через `edt_lib.check_bsl` +
`<QueryText>` форм) — 0,7 с, перед каждой загрузкой; унаследованные замечания — в базовый список, показываются только
новые. Исключение: «Изменения» — ключевое слово, но псевдонимом 8.5.1 его принимает (`QUERY_ALIAS_OK`).

**Помощники правки готовой выгрузки — в наборе, а не в скриптах проекта.** Свёрнутая группа, вкладка со связанным
списком, обёртка в страницы, события, скрытие, перестановка колонок, колонка ТЧ, своя форма списка с произвольным
запросом и основной таблицей — `designer_lib` (`form_*`, `dynamic_list_*`, `md_add_*`, `catalog_list_form`),
идемпотентны; проверены на копиях форм UP (well-formed, повтор ничего не меняет), формат — с форм, загруженных в 8.5.1.

Источник: UP, `инструменты/тест_ui.py`, `инструменты/платформа.py` (`линт`), ЛОВУШКИ У-18…У-20.

## Второй заход (18.10.2026): 110 → 67 с, выборочно ~15 с

**Ждать смены окна, а не фиксированную паузу.** Половина прогона была паузами после «команды» (0,7 с) и «закрыть»
(0,7 + 0,3 с). Ключ «заголовок активного окна | заголовок его формы» до действия; после — опрос каждые 0,05 с до
смены, предел — прежняя пауза, затем 0,1 с на дорисовку (`ЖдатьСмены_` в `reference/testing-ui/ТестUIМенеджер/`).
Шаг «команда» стал честным временем открытия формы — раньше её загрузка доливалась в следующий снимок.

**Выборочный прогон по `git diff`.** Обзор всех форм нужен редко; после правки 1–3 форм — блоки только этих объектов
(изменённый общий модуль тянет объекты, в модулях которых он упоминается): 14 шагов, 14 с.

**Снимки на сервере без видеокарты.** Windows Graphics Capture (`ffmpeg gfxcapture`, `windows-capture`) требует D3D11 —
на базовом адаптере и адаптере RDP «Failed to create D3D11VA device». Пока окно RDP свёрнуто или отключено, рабочий стол
не рисуется: «screen grab failed» у копии экрана, BitBlt по окну и `gdigrab` — значит, и непрерывная запись видео
не поможет. Рисует только PrintWindow, а он с любым флагом тормозит клиент на минуты. Выводить окно вперёд (Alt +
SetForegroundWindow) — навязчиво: пользователь отказался. Итог: копия экрана, если окно видно (проверка
`WindowFromPoint` в сетке 3×3 — иначе снимется окно, лежащее сверху: 64 снимка оказались окном приложения Claude),
иначе снимок пропускается с итоговой сводкой; PrintWindow — только явным ключом.

**Правило в памяти не держится — нужен хук.** Heredoc с `\` в Git Bash ломался после записи правила ещё дважды.
PreToolUse-хук (`tools/hook_heredoc.py`, в `.claude/settings.json` проекта, matcher `Bash`) отклоняет такую команду
кодом 2 с подсказкой; вывод — байтами UTF-8 (иначе Python на Windows пишет stderr в cp1251 и подсказка нечитаема).
