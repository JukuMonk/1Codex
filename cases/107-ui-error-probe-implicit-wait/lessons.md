# Симптом → причина → правило

После добавления проверки глобальной ошибки каждый UI-шаг занимал около
12 секунд. Причина — многократный `НайтиОбъект` для отсутствующего ErrorInfo:
поиск содержит ожидание. Умножение типов элемента и окон усилило задержку.

Для частого опроса ошибки читать `ПолучитьПодчиненныеОбъекты()` активного окна,
собрать индекс реально существующих имён, затем читать ErrorInfo и доступные
AdditionalInfo/ServerText. Глубину обхода ограничить по реальному дереву стенда.
Ни отсутствие поля, ни проверка альтернативного типа не должны создавать
дополнительные ожидания. Существующее действие по точному имени кнопки остаётся
отдельным поиском; не подбирать команды по похожим заголовкам.

Проверять ошибку перед/после действий и внутри ожиданий формы, а прогресс писать
после каждого шага в отдельный файл. Финальный журнал не использовать как сигнал
прогресса, если старый запускатель считает его появление завершением теста.

В исключении менеджера сохранять
`ПодробноеПредставлениеОшибки(ИнформацияОбОшибке())`, активную форму и сообщения.
Этот стек показывает выполнение менеджера, а не обязательно исходное серверное
исключение приложения. Короткий ErrorInfo нельзя выдавать за полный клиентский
стек. На стенде UP его дополнительно извлекали из журнала регистрации того же
запуска. Скрытые подробности не раскрывать неподтверждённой командой; кнопку
отправки отчёта об ошибке не нажимать автоматически.

Проверка изменения: положительные команды таблицы, намеренно отсутствующая
кнопка, намеренное исключение приложения, замеры отдельных шагов до/после,
проверка полного диагностического текста и отсутствия секретов в журнале.
Static-тест дополнительно запрещает `.НайтиОбъект(` в частом опросе ErrorInfo.

Ограничения: проверено на 8.5.1.1529 в файловой песочнице; стоимость обхода
большой формы и поведение другой платформы измеряются отдельно. Не переносить
числа 11996/330 мс как норматив для 8.3, SQL или удалённого тест-клиента.
