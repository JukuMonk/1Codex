# UI-тесты в 15 раз быстрее: снимок копией экрана вместо PrintWindow, один клиент на сценарий, проверка запросов до платформы

**Проект и платформа.** «ФРЕГАТ: управление проектами» (UP), своя конфигурация без EDT, 8.5.1.1529, файловая база;
настоящие нажатия — TESTMANAGER (`ТестUIМенеджер`, внешняя обработка) ведёт TESTCLIENT, `инструменты/тест_ui.py`;
17.10.2026.

**Задача.** Разбор сессии (ДиЗ-03/04 + редизайн 15 форм «Методологии»): из 134 мин чистого времени ~32 мин — ожидание
UI-прогонов на переднем плане, ещё 102 мин — фоновые прогоны; обзор всех форм подсистемы (176 шагов) шёл ~1700 с
десятью частями, части падали по таймауту 900 с. Пользователь: «Очень долго» → «внедряй ускорения».

**Что было.**
1. Сценарий дробился на части по 10–20 шагов (иначе — «не уложился в 900 с»); каждая часть — новый клиент,
   закрытие, пересборка менеджера.
2. Снимок окна (`PrintWindow` через PowerShell, потом по PID) — 1,8 с, а следующий шаг с динамическим списком —
   70–244 с. Списки «тормозили» только в тесте: пользователь медленных форм не видел.
3. Ошибки текста запроса («Ожидается имя» из-за `КАК В`) — только после подключения COM или загрузки в базу
   (минуты), дважды за сессию.

**Как нашли.** Длительность каждого шага в журнале менеджера (`[N мс]`) и замер каждого снимка в `тест_ui.py`:
медленным всегда был шаг ПОСЛЕ снимка, а с `UI_SHOT=screen` — нет.

**Что стало.** `before/тест_ui_цикл.py.fragment` → `after/тест_ui_снимок.py.fragment`; менеджер —
`reference/testing-ui/ТестUIМенеджер.Module.bsl` (паузы 2→0,7 с, 1→0,3 с, ожидания в циклах ×3,3); проверки —
`tools/designer_lib.py` (`check_query`, помощники правки форм).
