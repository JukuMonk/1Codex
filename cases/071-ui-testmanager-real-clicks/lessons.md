# Уроки

**Симптомы и причины.**
- «Тип не определен (ТестируемоеПриложение)» в журнале **тестируемого** клиента — интерпретатор лежит в общем глобальном модуле, а тип существует только у `/TESTMANAGER`. Литерал `Новый ТестируемоеПриложение(...)` не компилируется у всех остальных и ломает им весь модуль. Создавать по имени: `Новый("ТестируемоеПриложение", Параметры)`.
- «Ожидается имя переменной» — переменная `И` (ключевое слово), как и `ИЛИ`, `НЕ`.
- «Метод объекта не обнаружен» — имена из справки/памяти не совпадают с платформой. Фактические имена сняты с `bin\test.dll` (строки UTF-16): `reference/testing-ui/test_api_8.5.1.md`. У поля: `ПолучитьОтображаемыйТекст`, `ВыполнитьВыборИзВыпадающегоСписка`, `ПолучитьПредставлениеСпискаВыбора`.
- «В элементе управления отсутствует указанное значение» — выбирать нужно `ОтображаемыйТекст` строки подсказки целиком (наименование + код), а не набранную часть; подсказка приходит асинхронно — опрашивать.
- «Неподходящий тип элемента управления для вызванного действия» — поле только для чтения (надпись-итог); вводить в источник (строку таблицы).
- «Неподходящее состояние элемента управления для вызванного действия» — в редактируемой строке таблицы не уходить из ячейки (`ПерейтиКСледующемуЭлементу`), завершать строку `ЗакончитьРедактированиеСтроки`.
- «Метод не может быть вызван для данного объекта» у `ПолучитьТекстыСообщенийПользователю` — окно формы; сообщения есть только у основного окна.

**Что изменилось.** Уровень 9 `platform.py ui <сценарий>`: вставки в XML-копию (сервер — сценарий/итог/сигнал снимка через ХранилищеОбщихНастроек; глобальный клиентский модуль — интерпретатор; модуль после начала работы — запуск по `/C СценарийUI`), два клиента одной базы с паузой 15 с, снимки окна **тестируемого** клиента (`*<база>*TESTCLIENT` в фильтре процесса), на первой ошибке — окна, активная форма, сообщения, дерево элементов (имя, тип, заголовок).

**Правило.** Кнопки и поля искать **по имени** элемента (дамп формы даёт все имена), заголовок — запасной путь; проверять результат каждого шага («значение | Поле | ожидаемое», «значение | Номер» после проведения, «сообщения»). Первая разведка новой формы — сценарий «команда → форма → дамп».
