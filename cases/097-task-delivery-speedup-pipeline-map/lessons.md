# Уроки

**Сначала измерить, потом ускорять.** Разбор транскрипта по этапам и видам работы (модель думает / пишет код /
ждёт 1С / прочее) показал: 70 % — время модели, а не платформы. Ускорять 1С дальше почти бесполезно; срезать нужно
число ходов модели, раскопки кода и переделки.

**Каждый ход модели стоит 10–20 с.** Десятки одиночных команд (линт, загрузка, проверка, тест, разбор вывода) —
это десятки ходов. Конвейер `цикл` / `выпуск` со сводкой в конце делает то же за один ход; выпуск принимает косметику
Конфигуратора только в своих изменённых файлах (git diff), чужие расхождения — стоп.

**Карта вместо раскопок.** Один сгенерированный файл (`КАРТА.md`: реквизиты, дерево форм с событиями, процедуры
модулей с комментариями, экспорт общих модулей), обновляемый после каждой загрузки, — раздел объекта читается за
один вызов вместо grep по выгрузке.

**Переделки ловить до платформы.** Дубли процедур и синтаксис своих скриптов — в линт (секунды), а не CheckModules
после минутной загрузки; повторяющийся код тестов (сравнение ссылок, первая строка запроса) — в общий модуль.

**Тестовые данные — постоянные.** Объекты с меткой «ТЕСТ», создаваемые идемпотентно, вместо поиска подходящих
данных в копии базы при каждом прогоне.

**Вход проверять первым.** Заготовка по docx сразу видит пустой шаблон и раскладывает пункты; каркас отчёта получает
номера, объекты и замечания — остаётся вписать «сделано / как пользоваться».

**Параллельность и быстрый режим** — без доработок: независимые пункты (разные объекты, нет общих файлов) — в
отдельные сессии с worktree; быстрый режим модели ускоряет генерацию.
