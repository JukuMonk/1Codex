# Инвариант после каждого регистратора

Остаток по каждой паре склад/товар >=0 после каждого целого документа.
В module набора записей ПередЗаписью берёт исключительную управляемую
блокировку всего регистра; ПриЗаписи проверяет историю уже изменённых движений
в текущей транзакции. Отказ откатывает документ и движения. Нет обхода
по ОбменДанными.Загрузка. Обычную запись проведённого документа переводим
в режим Проведение в ПередЗаписью объекта; сохранять старые движения нельзя.

ОстаткиИОбороты(, , Регистратор, , ) без границ включают прошлое и будущее.
Выбирать парой КоличествоНачальныйОстаток и КоличествоКонечныйОстаток:
особенность расчёта виртуальной таблицы. Период и Регистратор обязательны.
Суммирование по секундам скрывает минус между регистраторами одной секунды.
Прямые движения внутри одного документа агрегируются атомарно.

Проверка: 209 сценариев с независимой Decimal-моделью (49 целевых,160
псевдослучайных,seed20261019);17 дополнительных (11 прямых записей,3 одной
секунды,3 повторения гонки двух сеансов);11 регрессионных;3 UI-сценария.
При отказах сравниваются сохранённые документы,ТЧ и движения до/после.
Второй сеанс реально ждёт незавершённую транзакцию первого, затем отказывает.

Полный скан и общая блокировка подходят небольшой учебной базе. Для большой
нужны измерения и оптимизация области блокировки с учётом старых И новых
измерений и даты; проверка только новых строк пропускает снятые движения.
Существующие минусы могут блокировать и постороннюю запись: до включения
проверить всю историю. Не обещать производительность на кластере по файловым
тестам. Два документа одной секунды упорядочивать по моменту платформы,
а не по порядку ввода или строковому представлению ссылки в другой системе.

При UI отказе записи набора платформа сначала показывает стандартное окно
ошибки; после OK подробный СообщениеПользователю доступен в панели сообщений.
Для PrintWindow Python должен быть DPI-aware, иначе правый/нижний край обрезан.
