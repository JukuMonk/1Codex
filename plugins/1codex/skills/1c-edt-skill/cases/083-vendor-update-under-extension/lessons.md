# Уроки кейса 083

1. **Расширение под новую поставку — трёхстороннее слияние по методам**: база — метод старой поставки, «наши» —
   метод ПРОД, «их» — метод новой поставки; `git merge-file -p --diff3` на строках без концевых пробелов. Конфликт,
   где общая часть пуста (обе стороны вставили в одно место), разрешается сам: сначала строки поставщика, затем
   доработка (доработка шла после типовой логики). Если после слияния метод = метод поставщика — доработку
   поставщик принял, перехват не нужен. Итог НПЦАП: 28 слились сами, в 8 правка уже у поставщика, 7 методов и
   2 схемы — вручную. Генератор — `cases/081-…/after/build_ext.py` (`NPCAP_TARGET`, `merge3`, `conflict`).
2. **Ручные решения — файлами, генератор их подхватывает**: `resolutions/<модуль>/<метод>.bsl` (полный метод, первая
   строка `//` — обоснование), `resolutions_new/<модуль>/<метод новой поставки>.bsl` (перехват метода-преемника,
   когда старого нет), `resolutions_templates/<…>/Template.xml` (схема целиком), `overlay/<версия>/…` (свои объекты
   и новые методы доработки под версию). Без решения метод не попадает в расширение, три версии кладутся в
   `conflicts/` — список конфликтов пуст = сборка готова.
3. **Схемы СКД, замещённые доработкой целиком**, — то же слияние по строкам XML; при конфликте — решение файлом.
4. **Проверить, не включил ли доработку поставщик** (у НПЦАП поставщик = автор доработок): отчёт КТГ в 3.0.25.3
   переименован и содержит доработку дословно — объект в «принятые поставщиком», не переносится.
5. **Собственные объекты доработки ломаются от переименований поставщика** (uuid объекта тот же, имя другое; регистр
   стал оборотным; ключ структуры параметров переименован). Найти: сканер ссылок по коду и схемам (`check_refs.py`
   кейса 081) + выполнение ВСЕХ отчётов и печатных форм доработки через COM (`after/print_forms.py`:
   `УправлениеПечатью.СформироватьПечатныеФормыДляБыстройПечати(Менеджер, ИдКоманды, Массив, Новый Структура)`),
   сравнение с ПРОД. Обработчики обновления поставщика показывают, во что переименовано.
6. **Прямой скачок через много релизов ломается на обработчиках обновления поставщика**, которые в коде новой версии
   ссылаются на позже переименованные объекты. Варианты: обновляться через промежуточный релиз (рекомендация
   владельцу) или временное расширение-исправление на время обновления ИБ (`after/update_fix_ext.py`:
   `&ИзменениеИКонтроль` с заменой имени, роли не меняет — БСП обновляет ИБ с ним; затем `/DeleteCfg -Extension`).
7. **COM и отчёты БСП 3.0.25**: `Настройки.ДополнительныеСвойства.Вставить("КлючПредопределенногоВарианта",
   Схема.ВариантыНастроек[0].Имя)` перед `СкомпоноватьРезультат`.
8. **Окно легальности обновления блокирует автотесты в клиенте** обновлённой базы (БСП показывает его до
   `ПослеНачалаРаботыСистемы`). Подтверждение — решение владельца базы, не агента: проверять формы на чистой базе
   новой поставки с расширением (начальное заполнение окна не показывает), данные — через COM.
9. **Отличия, которые вносит поставщик, отделять от ошибок переноса**: сравнить число записей регистров-источников
   отчёта до/после (у НПЦАП обработчик пересоздал выполненные регламентные мероприятия 477 → 490) — расхождение
   отчёта объяснено данными, а не кодом расширения.
