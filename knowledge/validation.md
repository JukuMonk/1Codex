# Проверка результата

Порядок от дешёвого к дорогому. Каждый шаг ловит свой класс ошибок; ни один
не заменяет остальные.

## 1. Структурные проверки (секунды, без EDT)

```bash
python tools/check_project.py <корень проекта EDT> --prefix <ваш префикс>
python tools/check_bsl.py <Module.bsl> [--common] [--hier Спр1,Спр2]
```

`check_project`: BOM/CRLF, регистрация в Configuration.mdo, папки форм и
их объявления, `parentSubsystem`, состав подсистем, ссылки на формы, дубли
uuid и имён, длина строк ≤ 1024, `saveWindowSettings`, `numberQualifiers`,
номера элементов и реквизитов, пути данных, спутники таблиц, обработчики в
модуле, `usePurposes MobileDevice` у корня при мобильных формах, директивы и
ловушки BSL. Песочница для прогона инструментов на примерах —
`python tools/make_sandbox.py` → `tests/sandbox/`.

Сравнение с образцом: `examples/` и `reference/` того же вида — тот же
порядок тегов, тот же состав свойств. Скелет элемента формы (порядок
дочерних тегов) должен совпадать с образцом; см. `tools/make_examples.py`
как эталон сборки.

Git: `git status`, `git diff` — только ожидаемые файлы; у типовой формы —
только вставленные фрагменты, не переформатирование.

## 2. EDT (минуты)

1. Обновить проект (F5) — файлы снаружи подхватываются только так.
2. Problems: ошибки модели (ссылки, типы, пути данных, директивы, запрос в
   цикле). Предупреждения о мобильном клиенте после включения `MobileDevice`
   — норма.
3. Открыть форму в редакторе: пустой предпросмотр — case 001–004 (метод
   лесенки проб, case 006).
4. Если EDT падает при обновлении базы с `formItem is null` при целых файлах
   — «Проект → Очистить…» (case 028).

Без EDT файлы проверяет `1cedtcli export` в чистое рабочее пространство
(10–15 минут; `reference/generators/проверить_экспорт_edt.py`).

## 3. Обновление базы (минуты–десятки минут)

Только из EDT. Новый объект — полное обновление (case 020). Ошибки
структуры («Ошибка SDBL», «нельзя добавлять объекты…») — `knowledge/deployment.md` §3.

## 4. Прогон в платформе (то, что ничем другим не ловится)

Запросы компилируются при выполнении; директивы, имена свойств, ключевые
слова, `Получить` регистра, кавычки — всё это видно только здесь:

- открыть каждую новую/изменённую форму (тонкий клиент; мобильную — и в
  мобильном клиенте);
- нажать каждую новую команду; выполнить сценарий, который читает данные с
  группами иерархических справочников (в базе разработчика групп может не
  быть — завести);
- отчёт: сформировать с отбором и без, с параметрами периода;
- роль: войти пользователем только с этой ролью;
- сообщения платформы читать целиком: «Поле объекта не обнаружено (X)»
  называет виновника; «Процедура или функция … не определена (X)» при
  существующей X — директива или чужой модуль.

## 5. Отчёт о проверке

В итоге писать точно, какой уровень пройден: «check_project без ошибок,
EDT Problems чисто, база обновлена инкрементально, форма открыта в тонком
клиенте, команда X выполнена» — и что осталось непроверенным. «Всё
работает» без прогона не утверждать.
