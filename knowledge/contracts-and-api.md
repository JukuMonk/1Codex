# Проверка контрактов формы и поиск API

Инструменты предотвращают известные ошибки до запуска 1С. Они не заменяют
компиляцию, права пользователя и выполнение действий в целевой песочнице.

## Стандартные команды

`python tools/workflow/form_contract.py <Form.xml> --platform 8.5.1.1529`
читает главный реквизит, привязки кнопок и исключения CommandSet. Метаданные
объекта определяются по структуре выгрузки либо задаются через `--metadata`.
Для проверенного профиля WriteAndClose у DocumentObject и проведение у
CatalogObject отклоняются; Posting=Deny запрещает команды проведения.
Другой профиль, неизвестная команда и отсутствие нужных метаданных дают
`needs_probe`, а не неподтверждённое утверждение о допустимости.

## UI до запуска

`python tools/workflow/ui_contract.py <scenario.txt> --form <Form.xml>`
поддерживает несколько `--form` и дополнение `--runtime <inventory.json>`
либо диагностическим деревом менеджера. JSON содержит массив `forms` с
`id`, `title` и `elements`; у элемента — `name`, `kind`, `title`, `table`,
`read_only`. ID совпадающей XML-формы — её абсолютный путь. Динамически созданные
стандартные кнопки брать из реального дерева, не выводить их имена из догадки.

Проверяются точные имена, типы, принадлежность колонки таблице, запрет правки
ReadOnly и необходимость `изменить | Таблица | Колонка` перед вводом ссылки.
Сортировка принимает видимый заголовок колонки. Смена текущей строки сбрасывает
состояние редактирования. Неизвестная форма/операция требует проверки, а не
наследует подтверждение предыдущего окна. SHA256 исходных XML обнаруживает
устаревший инвентарь. CLI: 0 ready, 1 blocked, 2 needs_probe.

## Повторное использование проверенных проб

[Каталог проб](../reference/probes/catalog.json) хранит платформу, происхождение,
фактически проверенное поведение и критерии. [Генератор EPF](../reference/probes/save_probe.py)
создаёт только файлы в пустом каталоге, не запускает 1С и не выбирает базу.

```
python reference/probes/save_probe.py catalog <выход> --object <Каталог> --test-marker <уникальный-маркер-тестовой-ИБ>
```

Документ должен поддерживать проведение; обязательные реквизиты целевого
объекта заполняются по его реальным правилам. Маркер — дополнительная проверка
строки подключения, не полномочие на работу с базой. До сборки и открытия
адаптер проверяет фактическую тестовую ИБ и пользователя. Пароли, токены и
полную строку подключения не передавать как маркер. При завершении приложения
в пробе закрытия оставлен штатный путь платформы.

Фрагменты динамического списка и независимого редактора требуют адаптации к
метаданным проекта. Каталог не объявляет их универсально проверенными EPF.

## Локальный индекс справки платформы

```
python tools/workflow/api_index.py build <распакованная-HTML-справка> <cache.sqlite> --platform <версия> --archive <исходный.hbk>
python tools/workflow/api_index.py search <cache.sqlite> "Открыть ТестируемоеПолеФормы" --platform <версия> --limit 5
```

Распаковка HBK выполняется существующим проверенным средством для конкретного
архива; собственный непроверенный декодер здесь не используется. После смены
HBK сначала обновить HTML. Индекс связывается с версией платформы, каталогом,
составом/размерами/mtime файлов и, если задан, SHA256 архива. Обновление
инкрементальное; повторный неизменённый вход не разбирает HTML заново.
Построение публикует прогресс каждые 100 документов и сохраняет старый кэш при
ошибке. Блоки script/style исключены, большие файлы явно перечисляются как
пропущенные. Поиск идёт по индексу русских и английских токенов с префиксом,
а не сканирует все HTML. Результат ограничен и содержит путь, фрагмент,
платформу и SHA256; совпавший исходник повторно проверяется по SHA256.

Совпадение не доказывает применимость метода в другом контексте исполнения.
Отсутствие совпадений не доказывает отсутствие API. При несовпадении версии
или источника кэш не выдаёт старый результат: требуется повторное построение.
