# Без EDT: формат выгрузки Конфигуратора и внешние обработки

Отработано на проекте АЗОТ (1С:ТОИР КОРП 3.0.8.1 + расширение ФРЕГАТ, платформа 8.3.27,
октябрь 2026): ТЗ «анализ потерь материальных потоков» сделано и проверено целиком без EDT —
исходники в XML Конфигуратора, сборка и загрузка пакетным Конфигуратором, проверка через COM
и настоящими нажатиями. Инструмент — `tools/designer_lib.py`. Case 074.

## 1. Цикл (HIGH)

```
DESIGNER /DumpConfigToFiles <каталог> [-Extension <имя>]     # исходники «как есть» → git
правка: designer_lib (XML) + .bsl руками
внешняя обработка: DESIGNER /LoadExternalDataProcessorOrReportFromFiles <корень.xml> <.epf>   (3 с)
конфигурация:      DESIGNER /LoadConfigFromFiles <каталог> -listFile <список> → /UpdateDBCfg
COM: ВнешниеОбработки.Создать(<.epf>, Ложь, ОписаниеЗащитыОтОпасныхДействий) → методы модуля объекта
UI:  1cv8c /TESTCLIENT -TPort N /Execute <.epf>  +  1cv8c /TESTMANAGER /Execute ТестUIМенеджер.epf /C "сценарий;журнал;N"
```

- Командная строка 1cv8 — СТРОКОЙ (`/P""`), с `/DisableStartupDialogs /DisableStartupMessages`
  (`testing.md`). Выгрузка ТОИР КОРП (22 тыс. файлов, 1,2 ГБ) — 2 минуты.
- Файлы выгрузки: UTF-8 с BOM, CRLF, табуляция. `designer_lib.write/normalize`.
- **8.5.1 (UP, case 085):** `designer_lib` по умолчанию пишет формат 8.3.27 — ставить `dl.VERSION = '2.21'`. Загрузка
  проходит, но выгрузка Конфигуратора 8.5.1 отличается косметикой: пространство имён `pal` в заголовке, в описании формы
  `UseInInterfaceCompatibilityMode`, порядок тегов поля `DataPath, ReadOnly, Title, ToolTip, ToolTipRepresentation,
  EditMode, Width…, ChoiceParameterLinks, TextSize, ContextMenu`. Для «база = исходник» после первой загрузки принять
  выгрузку как исходник (сверка 0), генератор считать разовым.
- **Правка готовой выгрузки (case 092):** `designer_lib` — `read_lf`, `xml_block`, `FormIds`, `form_field_xml`, `form_add_commands`, `form_add_event`, `form_item_event`, `form_hide`, `form_collapsible_group` (свёрнутая группа «Дополнительно»), `form_wrap_in_pages`, `form_add_page`, `form_related_list` (вкладка со связанным динамическим списком), `form_reorder_columns`, `form_move_element`, `md_add_ts_column`, `md_add_form`, `catalog_list_form` (своя форма списка: произвольный запрос + основная таблица, порядок тегов 8.5.1), `check_query`. Все идемпотентны.

## 2. Что выбирать: внешняя обработка, расширение или конфигурация (HIGH)

- **Внешняя обработка** — первый выбор для нового инструмента: конфигурацию и расширения не трогает,
  собирается за секунды, переоткрывается в том же сеансе, отдаётся через «Дополнительные отчеты и
  обработки» (`СведенияОВнешнейОбработке` в модуле объекта).
- **Типы расширения в метаданных .epf недоступны**: при сборке «Неизвестное имя типа
  CatalogRef.<объект расширения>». Реквизиты и колонки — `cfg:AnyRef` (`'AnyRef'` в designer_lib),
  объекты расширения — только в коде (запросы, `Перечисления.X`, `Метаданные.X` — в сеансе они есть).
- **Загрузка расширения из XML**: ГЕНЕРИРОВАННОЕ расширение (минимальные заимствованные формы, кейс 081) грузится
  целиком и надёжно. Ненадёжна ВЫГРУЗКА реального расширения: 8.3.27 даже без правок не загрузилась
  обратно («Исключение XDTO … Catalogs/<заимствованный>/Forms/ФормаСписка/Ext/Form.xml»), в том числе
  частично (`-listFile` с одним Configuration.xml): загрузка расширения разбирает все файлы.
- **Основную конфигурацию целиком из XML не грузить**: ломает ключи защиты вендоров (1С-Рарус, СЛК) —
  ловушка МВМ. Только `-listFile`/`-files`.
- Основная конфигурация не может ссылаться на объекты расширения: доработка над данными расширения —
  в само расширение или во внешнюю обработку.

## 3. Внешняя обработка в XML (HIGH, эталон — выгрузка рабочей .epf)

```
<Имя>.xml                                  корень: ExternalDataProcessor
<Имя>/Ext/ObjectModule.bsl                 модуль объекта — ВНУТРИ папки <Имя>, рядом с Forms
<Имя>/Forms/<Форма>.xml + /Ext/Form.xml + /Ext/Form/Module.bsl
<Имя>/Templates/<Макет>.xml + /Ext/Template.txt (TextDocument) | Template.bin
```

- Корень: `xr:ContainedObject` с постоянным `ClassId c3831ec8-d8d5-4f93-8a22-f9bfae07327f` и своим
  `ObjectId`; `GeneratedType` только `ExternalDataProcessorObject`; в свойствах — Name, Synonym,
  Comment, DefaultForm, AuxiliaryForm (без UseStandardCommands/Explanation).
- Модуль не в той папке — сборка проходит (код 0), а методов у объекта нет: через COM
  «AttributeError <unknown>.Метод». Сборка модули не компилирует — ошибки видны при `Создать` через
  COM («Ошибка инициализации модуля … (строка, колонка)») или при открытии формы.
- Порядок тегов поля ввода (по выгрузке): DataPath, Visible, ReadOnly, Title, TitleLocation,
  EditMode, Width, Height, HorizontalStretch, MultiLine, ChoiceButton, ClearButton, ContextMenu,
  ExtendedTooltip, Events. В надписи `Font` — ПЕРЕД `Title`. `AutoTitle=false` — сразу после `Title`
  формы, иначе заголовок окна «Синоним: Заголовок».
- Ловушка сборки строк BSL в PowerShell: замены `.Replace("…`n…")` молча не срабатывают на файлах с
  CRLF — правки делать Python (`io.open(newline='')`) с проверкой числа вхождений.

## 4. Проверка (HIGH)

- **COM**: ядро — в модуле объекта (`#Если Сервер Или … ВнешнееСоединение`), табличные части
  объекта — буфер модели; Python создаёт обработку, вызывает методы и сверяет результат с независимой
  реализацией алгоритма (расхождений 0 — тогда «работает»). Ссылки через COM сравнивать по
  `УникальныйИдентификатор()`; `None` реквизит `ЛюбаяСсылка` не очищает — `pythoncom.Empty`.
- **Форма**: `1cv8c … /Execute <.epf>` + снимок окна (`SHOT_PS` из `platform.py`). Копии базы БСП
  на старте спрашивает «база перемещена или это копия?» и перехватывает фокус —
  `БлокировкаРаботыСВнешнимиРесурсами.ЗапретитьРаботуСВнешнимиРесурсами()` через COM один раз.
  Предупреждение об опасных действиях — снять у пользователя копии (`ЗащитаОтОпасныхДействий`).
- **Настоящие нажатия без правки конфигурации**: интерпретатор сценария уровня 9 (`platform.py ui`)
  вынесен во внешнюю обработку-менеджер — `reference/testing-ui/ТестUIМенеджер.Module.bsl`
  (шаги: форма, кнопка, страница, надпись, поле, значение, строка, открыть, вопрос, закрыть, снимок,
  сообщения, дамп). Файлы — на сервере (`&НаСервереБезКонтекста`): синхронные файловые вызовы
  клиента в типовой могут быть запрещены. У `ТестируемаяФорма` нет `Закрыть` — закрывается
  `ТП.ПолучитьАктивноеОкно().Закрыть()`. Снимок окна тестируемого клиента — фильтр процесса
  по `TESTCLIENT` в командной строке.

## 5. Поле HTML во внешней обработке (HIGH, case 075)

- Страница — текстовый макет `<Имя>/Templates/<Макет>/Ext/Template.txt` (BOM, CRLF); исходник — `.html` в проекте,
  генератор копирует его в макет. Данные — JSON вместо заглушки `/*МОДЕЛЬ*/null` на сервере при создании формы.
- Элемент формы: `designer_lib.Form.html(path, …)` — `HTMLDocumentField` с шириной, высотой и растяжением.
- Если страница пересчитывает то же, что 1С, — общие индексы и сверка: режим `#selftest` в headless Edge
  (`--dump-dom`) против результатов COM на нескольких сценариях; расхождений 0 — тогда «совпадает».
- Мост 8.3.27: страница → 1С — очередь в `textarea#bridge_out` + подтверждение `out_ack` (опрос раз в секунду),
  1С → страница — `value` скрытого поля; функции страницы из 1С не вызывать (`html-field-and-templates.md` §3).
- Ошибки страницы — ранним отдельным `<script>`; для `--dump-dom` дублировать в `textContent`.
- Чужая библиотека (ECharts 1 МБ) — в тот же макет: метка `/*ECHARTS*/`, строки ≤900 с маркером `chr(1)` в конце куска,
  склейка `СтрЗаменить(Текст, Символ(1) + Символы.ВК + Символы.ПС, "")`; сверка `ГрафHTML()` через COM со страницей
  один в один. `requestAnimationFrame` — таймером до библиотеки; перерисовка — `replaceMerge: ['series']` (case 076).

## 6. Своя конфигурация с нуля (HIGH; кейсы 078, 084)

Отработано на ЖДРМ ПУЛЬС (8.3.27, совместимость 8.3.21, без БСП): метаданные — спецификацией на Python, модули — руками.

```
шаблон Configuration.xml = выгрузка ПУСТОЙ базы той же платформы (InternalInfo, мобильные функциональности)
спецификация → catalog_xml / enum_xml / information_register_xml / document_xml / common_module_xml /
               subsystem_xml / role_xml + rights_xml / scheduled_job_xml / constant_xml / md_command
            → configuration_child_objects (порядок видов CONFIGURATION_KINDS, папки KIND_DIRS)
load_config (ПОЛНАЯ: своя конфигурация, ключей вендоров нет) → update_db → check_modules
→ dump и сравнение с исходником по содержанию: 0 расхождений = построитель верен
```

- Полная загрузка допустима ТОЛЬКО для своей конфигурации; у типовых — `load_files` (§2).
- Роль «все права»: `rights_xml(set_for_new_objects=True)` без объектов (как `ПолныеПрава` БСП — там только запреты);
  её — в `DefaultRoles`, пока в базе нет пользователей.
- Формы списков и элементов поначалу не нужны: платформа строит их сама; команды объекта (`md_command`) видны и на них.
- Модуль объекта — файл `<Вид>/<Имя>/Ext/ObjectModule.bsl` (ссылка в XML не нужна); генератор только нормализует .bsl.
- Документ (HIGH, case 084): `document_xml`, несколько ТЧ, ссылка на свой документ в колонке ТЧ — загрузка и сверка
  0 расхождений. Своя форма документа: `cfg:DocumentObject.X`, `Объект.Number`/`Объект.Date`, колонка `LineNumber`,
  свойства `AutoTime=CurrentOrLast`, `UsePostingMode=Auto`, `RepostOnWrite=true`; модуль формы не обязателен.
  Представление ссылки — `Ext/ManagerModule.bsl` (`ОбработкаПолученияПолейПредставления` + `…Представления`).
- Нативная форма «красиво» без поля HTML (case 084): разметка — построителем (таблицы значений, страницы, надписи-
  показатели), шрифты, цвета и условное оформление — кодом в `ПриСозданииНаСервере`; выбор из ограниченного списка
  в колонке — `StartChoice` → `ПоказатьВыборИзСписка`. Образец — `cases/084-…/after/`.
- Клиентский код проверять в ВЕБ-клиенте: на клиенте нет `XMLСтрока`, `ЗаписьJSON` (кейсы 073, 084); ошибки сеансов —
  `ВыгрузитьЖурналРегистрации` через COM (`cases/084-…/after/журнал_ошибок.py`).
- .dt для показа на другом сервере: `/DumpIB` без держателей базы (клиенты, COM, Apache публикации) → проверка
  разворачиванием (`CREATEINFOBASE` строкой, `/RestoreIB` без `/N`) → COM; всё, что база досчитывает «до сейчас»,
  досчитать на весь период показа (`cases/084-…/after/dt_выгрузка.py`).
- Посев через COM: `Заполнить(None)` + `ПроверитьЗаполнение()` — как форма; даты — `XMLЗначение` с типом из
  `ОписаниеТипов` (не `datetime`: pywin32 сдвигает на пояс).

## 7. Доработки типовой → расширение; перенос данных; обновление поставки (HIGH, кейсы 081–083)

Отработано на НПЦАП (ТОИР КОРП 3.0.8.1 → 3.0.25.3, БСП, СЛК, 8.3.27, октябрь 2026): 41 новый объект и 43
изменённых типовых вынесены в расширение генератором, данные демобазы перенесены со сверкой 0 расхождений.

```
/DumpConfigToFiles ПРОД → Ext/ParentConfigurations/<Имя>.cf = поставка-база → /LoadCfg во вспомогательную → выгрузка
diff двух выгрузок (файлы, метаданные, методы) → генератор расширения → /LoadConfigFromFiles -Extension (целиком)
→ /UpdateDBCfg -Extension → /CheckModules -Extension → подключение к сеансу через COM (контроль перехватов)
→ сверка перехватчиков без платформы → формы в клиенте (/C) → отчёты и печать через COM
переход рабочей базы: выгрузить данные доработок → подготовить → /LoadCfg поставки → расширение → обновление ИБ без
расширения (БСП ПраваРолей) → включить → загрузить данные → сверка снимков и отчётов
```

- Генератор и проверки — образец в `cases/081-…/after/` (`build_ext.py`, `bsl_methods.py`, `diff_cf.py`, `diff_meta.py`,
  `verify_ext.py`, `check_refs.py`, `ext_activate.py`); перенос данных — `cases/082-…/after/`; обновление поставки —
  `cases/083-…/after/`. Это проектный код НПЦАП: брать технику, не имена.
- Изменённый метод → `&ИзменениеИКонтроль` (тело поставщика + `#Вставка`/`#Удаление`); формы — минимальные
  заимствованные, состав формы — кодом; изменённые коллекции — только добавленное.
- В заимствованный регистр поля не добавить при совместимости ≤ 8.3.25 → регистры-спутники (кейс 081 §5).
- Новая поставка: трёхстороннее слияние по методам и схемам, ручные решения файлами, сканер ссылок + выполнение
  отчётов и печати (кейс 083); прямой скачок через релизы может упасть на обработчиках поставщика.
