# Монитор выполнения задачи

В начале задачи агент запускает монитор в каталоге проекта, отправляет ссылку
в чат и сохраняет путь к журналу. Первая строка вывода содержит путь, вторая
содержит локальный адрес. При обычном запуске команды системный браузер открывает
монитор «Терминал». Для панели Codex передать <code>--no-browser</code> и открыть
этот адрес в панели текущего чата. Ссылка в выводе позволяет восстановить вкладку.
Один журнал сопровождает работу до итогового отчёта. Для пакета требуется локальный
Python 3.12+ и браузер на машине проекта. Путь к скрипту брать от установленного SKILL.md.

~~~powershell
python tools/workflow/pipeline.py start --project . --label "Проверить изменение списания"
~~~

Монитор читает журнал каждую секунду. В едином дереве 12 разделов атласа.
Нажать раздел, чтобы раскрыть узлы на месте, и узел, чтобы увидеть его попытки.
Одновременно можно открыть несколько ветвей. Полосы справа показывают время
каждой операции от начала прогона. Нажатие на событие открывает нужную попытку.
Фильтр по пункту учитывает ID из карточек требований.

Верхняя схема «Маршрут попыток» показывает записанные запуски слева направо.
Ветви от общего предшественника расходятся на отдельные дорожки. Пунктир
«Внутри этапа» показывает родителя вложенной операции. Нажатие на узел открывает
соответствующую попытку в дереве. Расстояния между узлами отражают связи.

Длительности читаются на общей шкале рядом со строками дерева. Цвет полосы
обозначает исход попытки. Штриховка ожидания начинается с явно записанного
ожидания и заканчивается при возобновлении или завершении операции.
Пустые интервалы между запусками сохраняются. Для цепочки исправления можно выбрать
шкалу от начала упавшей попытки до конца повторной или вернуться ко всему прогону.
Карточка сбоя сохраняет первый исход, сообщение журнала и отдельную длительность каждого шага.

Стрелки соединяют фактически записанные шаги. После сворачивания они приходят
к видимому предку. Янтарная пунктирная стрелка обозначает повтор, красный знак
сохраняет прежнюю ошибку после исправления. Карточка «Ошибка и успешный повтор»
появляется при наличии цепочки явно указанных предшественников до той же
проверки. В подробностях попытки указаны её родитель и предшественник.
Команда «Ещё узлы атласа» открывает незапущенные узлы раздела. Ссылки «По атласу»
показывают возможные переходы и раскрывают соседний узел в том же дереве.

**Работа агента.** Начать этап до действия и закрыть после получения результата.
Указывать ключ раздела или конкретного узла схемы. Команда begin возвращает ID.
Имена узлов берутся из [схем атласа](../docs/atlas/graph-layout.json).

~~~powershell
$timer = 'tools/workflow/timing.py'
$analysis = python $timer begin $journal "Уточнить условие отказа" --node analysis.criteria
python $timer end $journal $analysis
$lookup = python $timer begin $journal "Найти модуль документа" --node metadata.search --after $analysis
python $timer signal $journal $lookup progress "Найден обработчик проведения"
python $timer end $journal $lookup
python tools/project_cli.py lint --config platform.json --journal $journal --after $lookup
~~~

Для <code>check</code>, <code>test</code> и <code>release</code> исполнитель сам
записывает внутренние шаги, включая загрузку, компиляцию, COM и запуск
собственного TestManager, если выполняет их в этом прогоне. Для Vanessa,
стороннего COM-теста и других команд использовать <code>pipeline.py run</code>.
Обёртка открывает и закрывает узел по фактическому коду возврата команды.
Например, для настроенной тестовой базы:

~~~powershell
python tools/workflow/pipeline.py run $journal --name "Сценарии Vanessa" --node ui.vanessa --cmd python tools/vanessa.py platform.json features
~~~

Ручные этапы поиска, изменения BSL, демо-данных и
проверки описывает агент. Текст чата в журнал автоматически не попадает.

Для пункта требования использовать <code>task_plan.py begin</code> с прежними
параметрами и необязательными <code>--node</code>, <code>--after</code>.
<code>--parent</code> привязывает вложенный шаг к активному родителю.
<code>--after</code> указывает завершённого предшественника. Без него
монитор показывает хронологический переход между последовательными шагами одного
пункта и уровня вложенности. Параллельные шаги отображаются отдельно.
Старые журналы открываются командой <code>open</code>. Неопознанные
имена остаются в журнале без привязки к карте.

**Ожидание и исправления.** После 60 секунд без записи активный узел получает
пометку «Без событий». Агент может сообщить о реальном прогрессе, ожидании
внешнего ответа или остановке через <code>signal</code>. В адаптере
<code>run_monitored</code> использовать <code>on_event=journal_reporter(journal, stage_id)</code>
из <code>tools.workflow.watchdog</code>. Сигналы watchdog сохраняются в истории.
Монитор только читает результаты.

Ошибку завершать <code>end ... --status failed</code>, затем начинать исправление
с <code>--after ID_ОШИБКИ</code> и повторять исходный узел с
<code>--after ID_ИСПРАВЛЕНИЯ</code>. Первая попытка остаётся в журнале.
Причину описывать кратко, исключая пароли, команды подключения и бизнес-данные.

**Завершение.** После закрытия всех этапов выполнить команды ниже.
Экспорт сохраняет автономный HTML для просмотра после остановки сервера.

~~~powershell
python tools/workflow/timing.py finish $journal
python tools/workflow/pipeline.py export $journal маршрут.html
~~~

Сервер слушает только 127.0.0.1 и завершает работу через 30 минут без запросов.
Чтобы снова открыть прежний прогон после остановки, выполнить
<code>python tools/workflow/pipeline.py open ПУТЬ_К_ЖУРНАЛУ</code>.
Монитор восстановит прежнюю ссылку, если порт свободен. Если порт занят,
команда напечатает новый адрес. Открыть его на компьютере исполнителя.
В итоговом сообщении дать ссылку на экспортированный HTML для просмотра в любое время.
