# Роль — ПримерРоль

**Что демонстрирует.** Роль из двух файлов: `.mdo` (имя, синоним) и
`Rights.rights` (табы, xmlns `http://v8.1c.ru/8.2/roles`): права запуска
(`ThinClient`, `MobileClient`, `OutputToPrinter`, `SaveUserData`) на
Configuration и права на объекты — обработка `Use`/`View`, справочник
`Read`/`View`, документ `Read`/`View`/`Edit`/`Update`, регистр
`Read`/`Update`, подсистема `View`. HIGH — состав снят с работающей роли
водителя (`reference/Roles/мвмВодитель`).

**Обязательные файлы.**

```
ПримерРоль/ПримерРоль.mdo
ПримерРоль/Rights.rights
```

Регистрация: `<roles>Role.ПримерРоль</roles>`.

**Что можно менять.** Список объектов и прав (`edt_lib.rights_file`):
имя конфигурации в `Configuration.<Имя>` — **имя целевой конфигурации**,
не «ИмяКонфигурации» из примера. `setForNewObjects`, `setForAttributesByDefault`,
`independentRightsOfChildObjects` — флаги в шапке файла, как в типовых.

**Что согласовано.** uuid `stable_uid('Role/…')`; объекты прав должны
существовать (`check_project` проверяет ссылки на `Пример…`).

**Чего роль не даёт.** Одной своей роли мало: типовой клиент требует
базовых ролей конфигурации (в источнике — `БазовыеПраваБСП`,
`уатБазовыеПрава`, `ЗапускМобильногоКлиента`), RLS не задан. См.
`knowledge/roles.md` §3.
