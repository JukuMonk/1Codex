# Каталог ошибок

Только то, что реально случилось в проекте-источнике (коммиты — в
`cases/`). Формат: симптом → причина → неправильно → правильно → как
проверить → case. Confidence HIGH, если не сказано иначе.

## EDT не видит объект / объект не загружается

### Объект есть на диске, а в дереве EDT / конфигурации его нет
- Причина: нет строки в `Configuration.mdo`.
- Неправильно: создать `src/DataProcessors/X/X.mdo` и ждать.
- Правильно: `<dataProcessors>DataProcessor.X</dataProcessors>` последней в группе.
- Проверить: `tools/check_project.py` («не прописан в Configuration.mdo»).
- Case 021.

### «Ошибка добавления объекта … нельзя добавлять объекты метаданных без загрузки родительского объекта»
- Причина 1: новый объект (обработка, отчёт, роль, модуль, подсистема) при
  ИНКРЕМЕНТАЛЬНОМ обновлении базы.
- Причина 2: дочерняя подсистема без `<parentSubsystem>`.
- Правильно: полное обновление конфигурации ИБ один раз; `parentSubsystem`
  у каждой дочерней; устойчивые uuid.
- Проверить: `check_project` (parentSubsystem); в EDT — полное обновление.
- Cases 019, 020.

### «Файл объекта не существует …/Subsystems/X.xml» при полном импорте
- Причина: подсистема без `parentSubsystem` — её нет в модели.
- Case 019.

### «Ошибка SDBL: слишком большое значение описателя длины» при обновлении базы
- Причина: строковый реквизит длиннее 1024.
- Правильно: `Строка(0)` (неограниченная).
- Проверить: `check_project` / `check_mdo`.
- Case 024.

### «Свойство Use / FillFromFillingValue / FillValue не входит в состав объекта метаданных Attribute» (формат Конфигуратора)
- Причина: состав свойств реквизита зависит от владельца (справочник / ТЧ /
  документ); в EDT-аналоге у реквизита ТЧ нет `fillValue`.
- Case 025.

### «NullPointerException … "formItem" is null» при обновлении базы из EDT
- Причина: генератор переписал форму, открытую в редакторе EDT; файлы целы,
  сломана модель рабочего пространства.
- Правильно: «Проект → Очистить…»; закрывать редакторы перед генерацией.
- Проверить: `1cedtcli export` в чистое рабочее пространство проходит.
- Case 028.

## Форма не открывается / пустой лист в EDT

### Редактор EDT показывает пустой лист вместо формы (XML валиден)
- Причины (каждая ловилась отдельно): числовой реквизит без
  `numberQualifiers` (001); нет `saveWindowSettings` (002); номера колонок
  таблицы совпали с номерами реквизитов (003); таблица без спутников
  `searchStringAddition/viewStatusAddition/searchControlAddition` (004).
- Как найти: лесенка проб — формы, отличающиеся на один элемент (006).
- Проверить: `check_form`.

### Мобильная форма не открывается ни в EDT, ни в платформе
- Причина: у корня конфигурации нет `<usePurposes>MobileDevice`.
- Case 005.

### «Неверный путь к данным» при открытии формы в платформе
- Причина: `<segments>` ведёт к реквизиту, которого нет на форме (три поля
  сразу).
- Проверить: `check_form` (корень пути ∈ реквизитам).
- `knowledge/managed-forms.md` §5.

### Форма открылась, но «всё разъехалось»: поля строки по колонкам всей страницы
- Причина: у группы нет `showLeftMargin/united/throughAlign/currentRowUse` —
  сквозное выравнивание «Использовать».
- Case 007.

### Поле тянется до края формы, соседи уехали вправо
- Причина: `width` без `autoMaxWidth=true`.
- Case 008.

### Панель полей наверху, пустота, таблица прижата к низу
- Причина: группе в вертикальной колонке не задан `verticalStretch=false`.
- Case 009.

### Поле HTML: белый экран при живой странице
- Причина: нет `width`/`height` у поля — viewport нулевой высоты.
- Case 022.

### Поле HTML: пустая страница, «Поле обмена in_… не найдено»
- Причина: макет в LF (одна строка), строки длиннее допустимого, нет полей обмена.
- Case 023.

## Команда есть, но не работает / обработчик не вызывается

### «Процедура или функция с указанным именем не определена (ОткрытьФорму)» при нажатии кнопки
- Причина: процедура модуля формы без директивы → серверная.
- Case 011.

### «… не определена (ТочкаМаршрута)» при открытии, функция на месте
- Причина: вставка кода между директивой и объявлением — функция потеряла
  `&НаСервереБезКонтекста`.
- Case 012.

### «{ОбщийМодуль.X.Модуль(N,M)}: … не определена (ЧислоИлиНоль)»
- Причина: функция из чужого модуля вызвана без префикса; общий модуль
  проверяется только при выполнении.
- Case 013.

### «… не определена (мвмИерархияПоОтбору)» у процедуры `&НаКлиентеНаСервере`
- Причина не доказана; лечение — две процедуры (MEDIUM).
- Case 033.

### «Поле объекта недоступно для записи (Параметры)»
- Причина: переменная названа именем свойства формы.
- Case 010.

### Кнопка в мобильном клиенте спрятана в «ещё», в таблице «More actions»
- Причина: команды в панели; командная панель таблицы.
- Case 041.

## Ошибка клиент/сервер и платформы в бою

### Веб-клиент: отчёты «Не удалось сформировать отчет (пустой результат)», фоновый расчёт падает
- В `default.vrd` публикации `<debug enable="true" url=""/>` — «Ошибка регистрации предмета отладки в отладчике» в фоновом сеансе; выключить отладку, перезапустить веб-сервер. Case 073.

### Веб-клиент: «Процедура или функция с указанным именем не определена (ЗаписатьJSON)»
- `ЗаписьJSON`/`ЗаписатьJSON` на клиенте в веб-клиенте недоступны — литерал вручную или на сервере. Case 073.

### «Поле объекта не обнаружено (ОбменДаннымиЗагрузка)»
- Правильно `Объект.ОбменДанными.Загрузка`. Case 014.

### «Поле объекта не обнаружено (ПустаяСсылка)»
- Правильно `ПустаяСсылка()`. Case 032.

### «Поле объекта не обнаружено (Запрет)» — значение перечисления
- Имя значения из `.mdo`. Case 045.

### Кэш/регистр «находит» запись, которой нет
- `Получить` независимого регистра возвращает структуру всегда; читать
  запросом. Case 018.

### «Строка, не закрывающаяся кавычкой» — падает сборка всего пакета
- Одиночная кавычка в тексте запроса; пустая строка — `""""`. Case 015.

### «Ожидается имя» в запросе
- Псевдоним/реквизит — ключевое слово (`По`). Case 016.

### «Преобразование значения к типу Число не может быть выполнено» на чистой базе
- Группа иерархического справочника в запросе (NULL). Case 017.

### «Неверные параметры МАКСИМУМ»
- Агрегат по строке неограниченной длины; `ВЫРАЗИТЬ … КАК СТРОКА(150)`. Case 031.

### «Ожидается выражение "ВЫБРАТЬ"» — весь пакет запросов не выполняется
- Два `;` подряд после выброса запроса. Case 046.

### «Поле объекта не обнаружено (ТС)» при чтении результата пакета
- Индекс `Результаты[N]` сдвинулся после вставки запроса в середину. Case 042.

### «Ожидается символ ';'» после вставки в типовую процедуру
- Последний оператор типовой процедуры без `;`. Case 026.

### Форма пустая / данные не пришли, ошибка одна строчка в окне сообщений
- Необязательный расчёт внутри сборки данных не в `Попытка`. Case 043.

### «Процедура или функция с указанным именем уже определена (Состояние)» — толстый клиент
- Причина: имя функции серверного модуля совпало с глобальным методом; профилировщик EDT
  запускает толстый клиент.
- Правильно: переименовать; `check_bsl` (GLOBAL_METHODS). Case 047.

### «Ожидается имя процедуры» при открытии формы
- Причина: команда формы названа ключевым словом (`Прервать`). Case 057.

### «Преобразование значения к типу Число не может быть выполнено» на первой строке данных
- Причина: `Число + "строка"` — тип задаёт левый операнд. Case 058.

### «Нельзя изменять поле, содержащее объект данных формы»
- Причина: локальная переменная с именем реквизита формы в процедуре с контекстом. Case 059.

### «Переменная не определена (X)» в процедуре БезКонтекста
- Причина: обращение к реквизиту формы там, где формы нет. Case 060.

### Кэш модуля с повторным использованием «не работает»
- Причина: несуществующее значение `returnValuesReuse` (`DuringCall`) принято EDT молча. Case 048.

### Операция идёт секунды и минуты при «небольших» данных
- Причина: перебор O(N²), загрузка данных на каждый вызов, реквизит через точку в цикле,
  запись всех объектов пакета, геометрия «каждый с каждым», отбор без индекса.
- Правильно: профиль с целью «Сервер», затем cases 049–053, 055 по строкам профиля.

### «Неоднозначное поле "X.Ссылка"» при открытии отчёта или запроса
- Причина: псевдоним таблицы (обычно подзапроса) совпал с именем табличной части объекта запроса. Case 062.

### «Запись с такими ключевыми полями существует» при проведении второго документа на тот же ключ
- Регистр, подчинённый регистратору, уникален по измерениям во всём регистре; признак документа, по которому «последний перекрывает», должен быть измерением. Case 064.

### «Поле не найдено "…Код"» / «…ЭтоГруппа»; «Ожидается …» на псевдониме `В`
- Нет кода (`codeLength` 0), нет групп, псевдоним — ключевое слово. Case 065 (и 016, 017).

### «Не задано значение параметра …» в отчёте СКД
- Параметр в запросе без `{}` — `use=Always` и значение по умолчанию. Case 068.

### «Переменная не определена (СпособКодированияСтроки)» при щелчке в поле HTML
- Параметры ссылок страницы — hex, раскодирование своей функцией. Case 069.

## СКД

### Отчёт показывает только итоги, без строк
- Нет вложенной группировки детальных записей. Case 035 (MEDIUM).

### Запрос схемы падает в бою
- Те же правила, что в BSL (группы, ключевые слова); компилятор его не видит.
  Cases 015–017.

## Без EDT: выгрузка Конфигуратора и внешние обработки

### «Неизвестное имя типа - CatalogRef.<объект расширения>» при сборке .epf
- Причина: при `LoadExternalDataProcessorOrReportFromFiles` типы расширений не известны.
- Правильно: в метаданных `.epf` — `cfg:AnyRef`; объекты расширения — только в коде.
- Case 074; `knowledge/designer-format.md` §2.

### Собранная .epf без методов модуля объекта (COM: «AttributeError <unknown>.Метод»)
- Причина: `ObjectModule.bsl` не в `<Имя>/Ext/` (внутри папки объекта); сборка всё равно код 0.
- Case 074; `knowledge/designer-format.md` §3.

### «Исключение XDTO произошло при чтении файла …/Forms/…/Ext/Form.xml» при загрузке расширения
- Причина: выгрузка расширения 8.3.27 (заимствованные формы) не загружается обратно даже без правок, и частично тоже.
- Правильно: новый инструмент — внешней обработкой; расширение из XML не грузить.
- Case 074.

### «Неопознанный оператор» на ровном месте
- Причина 1: переменная с именем ключевого слова языка (`И`, `ИЛИ`, `НЕ`).
- Причина 2: метод у выражения `Новый Тип(...)` (`Новый Файл(П).Существует()`).
- Case 074.

### «Поле объекта недоступно для записи (Окно)» в модуле формы
- Причина: `Окно` — свойство формы; локальная переменная с этим именем = присваивание свойству.
- Правильно: другое имя (`ОкноКлиента`). Cases 010, 074.

### Таблица формы пустая, а счётчик/заголовок («Изменения (1)») верный — в тестовом клиенте
- Причина: вкладка, впервые показанная шагом `ТестируемаяГруппаФормы.Активизировать()` после возврата из другого окна, не отрисовывает строки (данные есть).
- Правильно: не чинить код по фантому; проверить переключением вкладки из формы (`Элементы.Страницы.ТекущаяСтраница`) — так и сделать в форме, если вкладку надо показать.
- Case 075.

### Страница поля HTML «висит» на заглушке, а поле ошибок пустое
- Причина: ошибка разбора основного скрипта гасит и его `window.onerror`; `--dump-dom` не видит `value`, выставленное из JS.
- Правильно: ранний отдельный `<script>` с `onerror`, состояние — в `textContent` обычного элемента. Case 075.


### ECharts в поле HTML: `Cannot set properties of null (setting 'innerHTML')` после щелчка
- Причина: перерисовка `setOption(…, true)` (notMerge) прямо в обработчике `click` — подсказка пересоздаётся, её отложенный показ пишет в удалённый элемент.
- Правильно: `setTimeout` после обработчика и `setOption(опции, {replaceMerge: ['series']})`. Case 076.

### Библиотека в поле HTML: `getRootNode is not a function`, `structuredClone`, `matchAll is not a function`
- Причина: WebKit поля HTML 1С 8.3.27 этих функций не знает (Edge знает — в браузере всё работает).
- Правильно: замены в раннем скрипте до библиотек; перед встраиванием прогнать по библиотеке поиск современных API. Case 076.

### Headless Edge молча пуст (код 0) — запуск из Bash-инструмента
- Причина: из Git Bash на Windows Server `msedge --headless --dump-dom/--screenshot` ничего не выводит даже для about:blank.
- Правильно: проверки страниц запускать из PowerShell. Case 076.


### Веб-клиент: «Сеанс отсутствует или удален» сразу после входа
- Причина: процесс веб-сервера упал (Apache: `child process exited with status 3221225477`). Модуль 8.5.1 на базе ТОИР 3.0 (8.3.27) — сбой в компоненте СЛК `licenceaddin` (журнал приложений Windows).
- Правильно: веб-модуль той же версии, что база; при чужой версии в рабочем Apache — отдельный экземпляр (служба, свой порт). Case 077.

### Зарегистрированная дополнительная обработка нигде не видна
- Причина: в базе (копии) выключена функциональная опция `ИспользоватьДополнительныеОтчетыИОбработки`.
- Правильно: включить константу; в ТОИР команда — в разделе («Дополнительные обработки»), не на начальной странице. Case 077.

### Опубликованная файловая база: регламентные задания не идут / Конфигуратор не загружает конфигурацию
- Причина: задания файловой базы выполняет процесс веб-сервера только после первого сеанса с его запуска; тот же процесс держит базу, пока жив сеанс.
- Неправильно: искать в default.vrd атрибут `allowexecutescheduledjobs` (его нет; `/AllowExecuteScheduledJobs` — ключ клиента).
- Правильно: после запуска Apache — короткий вход тонким клиентом `/WS"http://…/<имя>"`; на время загрузки конфигурации и копирования базы Apache останавливать. Case 077 (дополнение ZHDRM).


### «Поле "Наименование" не заполнено», хотя ПередЗаписью его составляет
- Причина: стандартная проверка заполнения идёт ДО записи.
- Правильно: в ОбработкаПроверкиЗаполнения при пустом наименовании убрать его из ПроверяемыеРеквизиты. Case 078.

### Дата через COM записалась на 3 часа раньше; `cn.Тип(...)` — AttributeError
- Причина: pywin32 переводит «наивный» datetime из местного пояса в UTC; глобального `Тип()` через COM нет.
- Правильно: `XMLЗначение(NewObject("ОписаниеТипов", "Дата").Типы().Get(0), "ГГГГ-ММ-ДДTЧЧ:ММ:СС")`. Case 078.

### Регламентное задание «каждые 20 с» идёт раз в минуту (файловая база)
- Причина: в файловой базе задания выполняет клиент, с шагом около 60 с; первый запуск — через ~2 мин после старта клиента.
- Правильно: частое обновление — обработчиком ожидания формы или серверная база. Case 078.

### Менеджер UI-тестов молча стоит, журнала нет
- Причина: «Предупреждение безопасности» при `/Execute` внешней обработки; в базе без пользователей его не отключить.
- Правильно: тестовая копия с пользователем, у которого `ПредупреждатьОбОпасныхДействиях = Ложь`; запуск с `/N`. Case 078.


## Различия desktop / mobile

- Смахивания по строке нет — только по страницам (030).
- Булевы колонки показываются «No»; командная панель таблицы — «More
  actions»; кнопки панели — в «ещё» (041).
- Одна форма с двумя назначениями работает в обоих клиентах; страницы
  `TabsOnTop` видны и на телефоне (006, 030).
