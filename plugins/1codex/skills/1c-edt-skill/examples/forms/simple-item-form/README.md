# Форма элемента справочника — ФормаЭлемента

**Что демонстрирует.** Форма объекта (`CatalogFormExtInfo`, реквизит
`Объект : CatalogObject.ПримерСправочник`, `main`, `savedData`,
`windowOpeningMode LockOwnerWindow`): горизонтальная группа код+наименование
(код с `width` + `autoMaxWidth` — case 008), вертикальные группы
`WeakSeparation` с заголовком, поле-ссылка, число с форматом, флажок,
многострочная строка, таблица ТЧ объекта `Объект.Точки` с командной панелью
(объектная таблица: `object_tabular_table`). У каждой группы четыре
свойства (case 007), у таблицы три спутника (case 004), у формы
`saveWindowSettings` (case 002), обработчик `OnCreateAtServer` есть в
модуле. HIGH.

**Обязательные файлы.** `ПримерСправочник/Forms/ФормаЭлемента/Form.form`,
`Module.bsl`; в .mdo справочника — `<forms>` + `defaultObjectForm`
(`examples/metadata/catalog`). Копия лежит внутри примера справочника,
чтобы `scaffold` брал объект целиком.

**Что можно менять.** Поля и группы (`edt_lib.field`, `usual_group`), их
порядок; заголовки (`title` — только когда отличается от синонима
реквизита); ширины. Путь данных каждого поля — существующий реквизит
объекта (`Объект.Имя`, стандартные `Объект.Code`, `Объект.Description`);
колонки ТЧ — `Объект.Точки.X`.

Нельзя: перенумеровывать элементы вручную (одно пространство для
элементов, второе для реквизитов+колонок, третье для команд — case 003),
убирать спутники/свойства групп/`saveWindowSettings`, писать умолчания
(`visible=false` → убрать тег; case 027).

**Что согласовано.** Имена реквизитов ↔ `.mdo` справочника; обработчики
`<handlers>` ↔ процедуры модуля с директивами.

**Похожее.** `knowledge/managed-forms.md` §1–5; `forms/record-form`
(форма записи регистра — та же анатомия), `metadata/document` (форма
документа); `reference/Catalogs/мвмУзлыКарты/Forms/ФормаЭлемента` (боевая).
