# tests/tasks — задачи для проверки модели

24 задачи. Каждая — с исходными данными, ожидаемым результатом и критериями
успеха; решения и эталоны — в `tests/expected/` (модели их не показывать до
проверки). Площадка — копия `tests/sandbox/` (пересобрать: `python
tools/make_sandbox.py`); задачи, требующие EDT или базы, помечены [EDT] /
[БАЗА] — их критерий проверяет человек.

Порядок для первого знакомства: T06, T07, T01, T03, T09, T11, T13, T15 —
они ловят самые дорогие ошибки (пустой лист формы, падение в бою, объект,
которого нет для конфигурации).

## Метаданные

**T01. Новый справочник.** В песочнице создать справочник `ТестКонтрагенты`
(синоним «Контрагенты (тест)»): реквизиты `ИНН` Строка(12), `Активен`
Булево, `Тип` — ссылка на `ПримерПеречисление` с проверкой заполнения;
ТЧ `Контакты` (`Имя` Строка(100), `Телефон` Строка(20)); формы элемента и
списка. Критерии: `check_project tests/sandbox` — 0 ошибок; в
`Configuration.mdo` есть строка `<catalogs>Catalog.ТестКонтрагенты</catalogs>`;
справочник добавлен в `content` подсистемы `ПримерГруппа` и в `.cmi`; в
роль `ПримерРоль` — `Read`/`View`; uuid объекта и реквизитов детерминированы
(повторная сборка даёт те же); порядок тегов реквизита как в
`examples/metadata/catalog`. Решение: `expected/T01.md`.

**T02. Реквизит в существующий объект.** Добавить в `ПримерСправочник`

Строка(50); вывести `Описание` на форму элемента. Критерии: длина 2000 не
записана (должна стать неограниченной 0 — case 024, с пояснением в

закрывающим `</attributes>`/`</tabularSections>` своего владельца, а не

`dataPath Объект.Описание`, многострочное; `check_project` 0 ошибок.
Решение: `expected/T02.md`.

**T03. Регистр сведений.** Создать независимый регистр `ТестСмены`:

**T05. Переименование.** Переименовать `ПримерОбработка` в
