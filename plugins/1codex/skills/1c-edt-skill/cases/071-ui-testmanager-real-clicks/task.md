# Настоящие нажатия: управляющий клиент /TESTMANAGER ведёт тестируемый /TESTCLIENT

**Объекты.** Сценарий пользователя в тонком клиенте: «Выявленный дефект → Смета (на основании) → Заказ на ремонт (на основании)» — ввод текста, выбор из подсказки, кнопки формы, строка табличной части, проведение.

**Проект: ФРЕГАТ EAM (EDT 2026.1, платформа 8.5.1.1529, режим совместимости 8.3.16, БСП 3.1.3).**

**Задача.** До этого уровня кнопки «нажимались» вызовом обработчика из тестовой вставки (`ПолеПанелиПриНажатии(...)` с подставленными данными события): не проверялись видимость и доступность команд, события `ПриИзменении` от ввода, выбор из списков, проверки заполнения при проведении. Нужен прогон, в котором платформа отрабатывает всё, как при живом пользователе, без участия человека.

**Результат.** `tools/platform.py` (команда `ui <сценарий.txt>`) (уровень 9, `knowledge/testing.md` §9). Сценарий из 27 шагов прошёл целиком и провёл заказ на ремонт; до исправления нашёл реальную ошибку конфигурации: форма дефекта не заполняла организацию и подразделения по объекту эксплуатации, и заказ в конце цепочки не проводился («Не заполнена организация», «Поле "Производственное подразделение" не заполнено»). Ни EDT, ни уровни 1–8 этого не видели.

**Confidence:** HIGH (API и приёмы проверены прогоном; список методов снят с test.dll 8.5.1).
