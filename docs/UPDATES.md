# Как владельцу обновлять 1Codex

Исходник навыка один: файлы в ветке `main` репозитория JukuMonk/1Codex.
Редактируйте SKILL.md, knowledge, tools и cases обычным способом, затем
публикуйте коммит в `main`. Не редактируйте вручную ветку `plugin`.

После каждого push GitHub Actions **Publish 1Codex plugin**:

1. Собирает пакет из отслеживаемых файлов исходного навыка.
2. Проверяет ссылки, 101 кейс (или актуальное число), Python, песочницу и ZIP.
3. Назначает версию `1.0.<номер запуска>` и публикует marketplace в ветку `plugin`.

Сборку можно повторно запустить через **Actions → Publish 1Codex plugin → Run workflow**.
Если проверка не прошла, ветка `plugin` сохраняет последнюю рабочую сборку.
Статус и validation.json доступны в Actions. Установка у коллег отслеживает
ветку `plugin`, а не фиксированный коммит.

Windows-установщик коллег создаёт ежедневную задачу, обновляющую marketplace
и установленный плагин командами клиента. Изменения не подменяют инструкции
внутри уже открытого чата: начните новый чат после обновления.
На macOS/Linux обновление выполняется командами из инструкции установки.

Обновление установочного PowerShell-скрипта в GitHub не заменяет уже установленную
задачу и её скрипт: для изменения механизма обновления коллега повторно запускает
новый установщик. Сами материалы навыка обновляются через marketplace.

Проверки кода конфигурации в 1С выполняются отдельно: CI пакета не запускает 1С.
Репозиторий публичный, поэтому храните настройки и данные конкретных баз вне него.
