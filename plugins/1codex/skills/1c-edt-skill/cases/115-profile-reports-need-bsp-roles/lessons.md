# Уроки case 115

Уверенность: HIGH для БСП 3.1.3 на 8.5.1, проверено прогоном 49 отчётов под профилем.

- Задание отчёта падает «Нарушение прав доступа» на `Константы.НастройкиКолонтитулов`: нужна роль `ЧтениеВариантовОтчетов`.
- Затем форма падает на клиенте «Преобразование значения к типу Булево» (`ФормаОтчета`, элемент `ВыбратьНастройки`).
  Кнопка привязана к `Form.StandardCommand.LoadReportSettings`, платформа не создаёт её без права сохранения данных
  пользователя. Нужна роль `СохранениеДанныхПользователя`; роль личных вариантов не помогает.
- Вывод табличного документа — `ВыводНаПринтерФайлБуферОбмена`.
- Vanessa это не ловит: шаг «нет сообщений» зелёный, ошибка только в журнале регистрации (`_$Job$_.Error`,
  `_$PerformError$_`). После прогона под профилем читать журнал.
- Тест только под администратором не доказывает ничего о рядовом пользователе: менеджер под администратором,
  клиент под профилем — ключ `va_client_usr` в `tools/vanessa.py`.
- Пользователь с профилем через COM: обычная запись справочника `Пользователи` очищает связь с пользователем ИБ,
  нужна запись с `ОбменДанными.Загрузка = Истина`. Роли после этого — `УправлениеДоступом.ОбновитьРолиПользователей`.
- `Записать()` из кода не вызывает проверку заполнения, форма вызывает: чтобы получить текст сообщений, сначала
  `ПроверитьЗаполнение()` и `ПолучитьСообщенияПользователю(Истина)`.
- Подписка БСП `ЗаписатьВерсиюОбъекта` только для справочников: документ в `ВерсионируемыеДанныеОбъект` даёт
  «Имя события недопустимо для указанного источника». Для документов — своя подписка на `ЗаписатьВерсиюДокумента`.
- Изменение поставляемых профилей и обработчики `Версия = "*"` доходят до рабочей базы только при новой версии конфигурации: при той же версии `delta_update.py` пишет «обновление ИБ: НеТребуется», роли пользователей не меняются. После обновления читать состояние базы, а не только код возврата.
