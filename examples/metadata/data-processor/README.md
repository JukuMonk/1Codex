# Обработка — ПримерОбработка

**Что демонстрирует.** Обработка с одной основной формой: командная панель
с тремя кнопками (`Заполнить` — по умолчанию, `Записать`, `ОтметитьВсе`),
поля отбора (`ТолькоАктивные` флажок, `Шаблон` строка), таблица значений
`Строки` (Отметка, Элемент, Комментарий, Состояние; выделение
`MultiRow`), реквизиты формы с колонками в ОДНОМ пространстве номеров
(case 003), команды формы в своём (`formCommands`), автокомандная панель
без автозаполнения (`autoFill=false` — кнопки только свои). Модуль: клиент →
«…НаСервере» → серверная работа, все процедуры с директивами. HIGH — форма
той же сборки, что боевая «Привязка пунктов» (`reference/DataProcessors/мвмПривязкаПунктов`).

**Обязательные файлы.**

```
ПримерОбработка/ПримерОбработка.mdo         ← <forms>, <defaultForm>
ПримерОбработка/Forms/Форма/Form.form
ПримерОбработка/Forms/Форма/Module.bsl
```

Регистрация: `<dataProcessors>DataProcessor.ПримерОбработка</dataProcessors>`;
в подсистему — `content` + команда `DataProcessor.ПримерОбработка.Command.Открыть`
в `CommandInterface.cmi` (`edt_lib.OPEN_COMMAND`); в роль — `Use`, `View`.

**Что можно менять.** Набор полей и колонок (`value_table`: колонки
`(имя, подпись, вид, только чтение)`), команды (`form_command` + кнопка
`bar_button` + процедура в модуле с тем же именем), реквизиты формы
(`form_attribute`; для таблицы — колонки с типами). Не трогать: спутники
таблицы (case 004), четыре свойства групп (case 007), `saveWindowSettings`
(case 002), `numberQualifiers` у числовых реквизитов (case 001).

**Что согласовано.** uuid `stable_uid('DataProcessor/…')`; `<forms>` ↔ папка
`Forms/Форма`; `CatalogRef.ПримерСправочник` у колонки `Элемент`;
обработчики `<handlers>`/команды ↔ процедуры модуля (`check_form` сверяет).

**Похожее.** `knowledge/managed-forms.md` §4–5; `forms/html-field-form`
(обработка с полем HTML), `mobile/mobile-form` (обработка с мобильной формой);
`reference/DataProcessors/мвмАРМДиспетчера` (большая боевая форма с двумя формами в одной обработке).
