# Порядок списка переносится явно

После первого перемещения новая обработка исполняемой СКД снова возвращала
порядок вставки: программный Порядок динамического списка не был перенесён
в полученные исполняемые настройки. Структура и выбор деталей также могли
быть пустыми.

В серверной процедуре формы получить исполняемую схему и настройки; задать
детальную группировку с авто-выбором. Если программный Порядок заполнен,
скопировать его элементы в общий порядок настроек, затем перенести итоговый
порядок в группировку деталей. Выполнять СКД с актуальными отборами списка.
Полный алгоритм записи и бизнес-ограничения остаются в проекте.

Одного удачного перемещения недостаточно: повторить вниз/вверх и
перенумерацию, проверить текущую строку и видимый порядок через TestClient,
затем сохранённые номера через COM. Не восстанавливать видимый порядок
запросом с фиксированным ORDER BY, игнорирующим выбор пользователя.

Пример after — точный фрагмент действующей формы УП на 8.5.1.1529;
другие версии и сочетания пользовательских группировок требуют проверки.
