# T14 — пустой лист в EDT

Правильный порядок (case 006, `knowledge/managed-forms.md` §9):

1. Не объяснять пустой лист свойствами формы («мобильная», «с таблицей») —
   EDT не сообщает, что именно неполно; это гадание, стоившее четырёх часов.
2. Сначала `python tools/check_project.py` — ловит четыре известные причины:
   `numberQualifiers` (001), `saveWindowSettings` (002), дубль номера
   реквизита/колонки (003), спутники таблицы (004).
3. Если чисто — лесенка проб: серия форм, каждая на один элемент больше
   предыдущей (`reference/generators/проба_мобильной_формы.py`, ключ `--убрать`);
   обновить проект, открыть каждую, найти ступень, на которой форма
   пропадает; сравнить этот элемент с образцом из `examples/`/`reference/`
   по скелету тегов.
4. Если форма была перезаписана снаружи при открытом редакторе и EDT падает
   с `formItem is null` — файлы целы, сломан образ проекта: «Проект →
   Очистить…» (case 028); проверить файлы можно `1cedtcli export`.
5. Правку файлов снаружи EDT подхватывает только после «Обновить» (F5).

Ответ без лесенки проб и с диагнозом «EDT не рисует формы с одним
мобильным назначением» — неверный (опровергнуто, case 006).
