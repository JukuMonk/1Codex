# Уроки

**Своя конфигурация, написанная с нуля, грузится ЦЕЛИКОМ** (`designer_lib.load_config` — `/LoadConfigFromFiles <каталог>`
без `-listFile`). Запрет полной загрузки (кейс 074, МВМ) — из-за ключей защиты вендоров типовых; у своей конфигурации их нет,
а частичная загрузка корня без `Ext/*` стирает модули приложения. Шаблон `Configuration.xml` — выгрузка пустой базы той же
платформы; генератор подставляет имя, синоним, роли, совместимость и `ChildObjects` (`configuration_child_objects` —
порядок видов как в выгрузке 8.3.27).

**Построители объектов конфигурации — в `designer_lib`** (с 09.10.2026): `catalog_xml`, `document_xml`,
`information_register_xml`, `enum_xml`, `constant_xml`, `common_module_xml`, `subsystem_xml`, `role_xml` + `rights_xml`,
`scheduled_job_xml`, `md_command`. Поле — кортеж `(имя, тип[, заголовок[, опции]])`, хвост свойств зависит от владельца
(у реквизита справочника `Use`, у измерения `Master/MainFilter/DenyIncompleteValues/TypeReductionMode`). Порядок
`ChildObjects`: справочник — реквизиты, ТЧ, формы, макеты, команды; документ — реквизиты, ФОРМЫ, ТЧ, макеты, команды;
регистр — ресурсы, реквизиты, измерения, формы. Свойства команды: Group, CommandParameterType, ParameterUseMode,
ModifiesData, Representation, ToolTip, Picture, Shortcut.

**Доказательство построителя — обратная выгрузка.** Загрузить, `/DumpConfigToFiles`, сравнить с исходником по содержанию
(без BOM и хвостового перевода строки; `ConfigDumpInfo.xml` пишет только Конфигуратор). 0 расхождений — формат верен.
Новый вид объекта считать непроверенным до такой сверки (ZHDRM: `платформа.py сверить`).

**Роль «все права» — `rights_xml(set_for_new_objects=True)` без объектов.** Так устроена `ПолныеПрава` БСП: перечислены
только ЗАПРЕТЫ, остальное разрешено. Её же — в `DefaultRoles`, пока в базе нет пользователей.

**Наименование, которое составляет `ПередЗаписью`, убирать из `ПроверяемыеРеквизиты`**, иначе стандартная проверка
(идёт до записи) требует его и в форме, и в `ПроверитьЗаполнение()`. Посев через COM, вызывающий `Заполнить` и
`ПроверитьЗаполнение`, находит такие ошибки модулей раньше пользователя.

**Даты из Python в 1С через COM — не `datetime`.** pywin32 считает «наивное» время местным и переводит в UTC:
`09.10 00:00` (MSK) приходит как `08.10 21:00`. Глобального `Тип()` через COM нет (как и `Формат`, `ТекущаяДата`) —
тип берётся из `NewObject('ОписаниеТипов', 'Дата').Типы().Get(0)`, дата — `XMLЗначение(тип, 'ГГГГ-ММ-ДДTЧЧ:ММ:СС')`.

**UI-тесты внешней обработкой-менеджером — в копии базы С пользователем**, у которого
`ЗащитаОтОпасныхДействий.ПредупреждатьОбОпасныхДействиях = Ложь`. Без пользователей «Предупреждение безопасности»
при `/Execute` ждёт ответа вечно; диалог виден в списке окон процесса заголовком «1С:Предприятие». Менеджеру нужен шаг
`команда | e1cib/list/…` (`ТП.ПолучитьАктивноеОкно().ВыполнитьКоманду`) — в своей конфигурации формы открываются
навигационными ссылками; с 09.10.2026 шаг есть и в эталоне `reference/testing-ui/ТестUIМенеджер.Module.bsl`.

**Модули после генератора правятся скриптом.** Генератор приводит .bsl к BOM+CRLF; Write сохраняет «пустые» строки
без табуляции — Edit по образцу из памяти не находит фрагмент. Писать модуль до прогона генератора, править — Python
с `newline=''` и проверкой числа вхождений.
