# Обновление доработанной УТ по цепочке релизов: обработчики обновления, отложенное обновление, ставки НДС 5/7/22

**Проект и платформа.** «Фрегат» — УТ 11.4.6.188 с доработками (ПРОД), цепочка 11.4.12.109 → 11.4.14.181 →
11.5.8.443 → 11.5.12.270 → …; 8.3.27.2342, серверная база (MS SQL 2025), 30+ млн записей регистров; 15–18.10.2026.
Скрипты — `C:\gold\mix\tools` (`migrate_chain.py`, `update_ib.py`, `deferred_status.py`, `vat_rates.py`).

**Задача.** Пройти звенья без пропуска (отложенные обработчики звена — до загрузки следующего), доработки — в
расширение под финальный релиз; ставки НДС 5/7/22, добавленные доработкой значениями перечисления, сохранить в данных
при переходе поставщика на справочник «Ставки НДС» (11.5.8) и слить со ставками поставщика позже (11.5.22+).

**Что пошло не так.**
1. Клиент `/C"ЗапуститьОбновлениеИнформационнойБазы;ВыполнитьОбновлениеИЗавершитьРаботу"` на 11.5.8 (БСП 3.1) ведёт
   обновление ФОНОВЫМИ заданиями; сторож «ИБ всё ещё требует обновления → клиент стоит» снимал его посреди работы.
   Снятый процесс клиента оставляет в кластере «спящий» сеанс — следующий запуск: «Обновление уже выполняется».
2. После `/UpdateDBCfg` 11.5.8 обработчики шли запросами по часу с 2+ млрд логических чтений — устаревшая статистика
   СУБД после реструктуризации. `EXEC sp_updatestats` (14 с) — запросы снова секунды/минуты.
3. Регистрация данных `Справочники.Контрагенты.СгенерироватьОбъектыРасчетов` — один SQL-запрос (договоры × ~30
   таблиц документов/регистров) ~1,5 ч даже после статистики. Не завис: по `sys.dm_exec_query_profiles` видно
   rebind по договорам.
4. Отложенные: регламентное задание не запускалось — в базе ПРОД расписание «с 19:00 каждые 60 с» (после полуночи —
   до вечера ничего). Синхронный запасной путь `ОбновлениеИнформационнойБазыСлужебный.ВыполнитьОтложенноеОбновлениеСейчас`
   — ОДНОПОТОЧНЫЙ: группа перехода на объекты расчётов (`РасчетыСКлиентами` и ещё ~15 многопоточных обработчиков,
   650+ тыс. регистраторов) — 11+ ч. Метод задания `ВыполнитьОтложенноеОбновление` разово не помогает: в цикле
   проверяет `Задание.Расписание.ТребуетсяВыполнение` и выходит.
5. Своё условие «25 мин без смены статусов = зависло» ложно срабатывало при многопоточном обновлении.
6. Таблица регистрации изменений объекта (`_ReferenceChngR…`) — не очередь обновления: там же узлы планов обмена
   заказчика. Очередь обработчика — строки узлов плана `ОбновлениеИнформационнойБазы` (`JOIN _NodeNNNN`).
