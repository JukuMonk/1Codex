# Обязательный учёт времени в разработке 1С

Правило действует для **каждой задачи разработки на 1С**: EDT, XML Конфигуратора,
расширения, внешние обработки, генераторы и исправления инструментов. Размер
задачи не отменяет замер. Начинать журнал перед изучением задачи, завершать
после проверки и подготовки отчёта. Если правило подключено посреди работы,
указать начало фактического замера; прошлые длительности не восстанавливать
по догадке. Возобновляя задачу, продолжить журнал или связать новый с предыдущим.

## Этапы

Разделять фактически выполняемые этапы: анализ постановки и метаданных;
реализация; статические проверки; подготовка песочницы и резервной копии;
загрузка и обновление; проверка модулей; COM; UI; исправления и повторные
прогоны; снимки и отчёт; выпуск и сверка. В небольшой задаче можно объединить
близкие этапы, сохраняя отдельные проверки. Пропущенные этапы обозначать как
«не выполнялся», а не нулём секунд. Неудачные попытки не удалять.

Ожидание пользователя/доступа/внешнего задания отмечать отдельным этапом,
при возобновлении закрывать его. Обычное ожидание запущенной проверки входит
в длительность проверки. У каждого интервала сохранять task/run ID, stage ID,
родителя при вложенности, UTC начала/конца, длительность и статус. Не писать
в журнал пароли, токены, строки подключения, командные аргументы и бизнес-данные.
Названия задач и этапов должны быть короткими и не содержать секретов.

## Команды

Стандартная библиотека Python, без подключения к 1С. PowerShell, путь к набору
брать из реально прочитанного SKILL.md:

```powershell
$timer = '<skill>/tools/workflow/timing.py'
$journal = python $timer start --project '<project>' --label 'task-123'
$phase = python $timer begin $journal 'Анализ'
# Изучение постановки и исходников, в том числе между вызовами инструментов.
python $timer end $journal $phase
$phase = python $timer begin $journal 'Реализация'
# Изменения.
python $timer end $journal $phase
$phase = python $timer begin $journal 'Проверка'
# Проверки; при сбое закрыть --status failed и начать новый этап исправлений.
python $timer end $journal $phase
python $timer finish $journal
python $timer show $journal
```

Сохранить выданные пути и ID в контексте задачи: PowerShell-переменные между
разными процессами запуска не сохраняются. `begin --parent <stage-id>` задаёт
вложенность. Сначала закрывать детей, затем родителей. `end` и `finish`
принимают `--status ok|failed|interrupted`. Незавершённый этап после аварии
закрывать как interrupted; позднее закрытие включает время простоя, это
отдельно пояснять в отчёте. Одинаковое имя не заменяет прежний интервал.

Для Python-адаптера добавить `tools/workflow` в sys.path, импортировать `timing`
и применять `with timing.stage(journal, 'COM'):`. Этот контекст дополнительно
измеряет время через perf_counter. Межпроцессные CLI-интервалы используют UTC
wall time и зависят от корректности часов ОС. После перевода часов такой замер
помечать как недостоверный; модуль не восстанавливает потерянное время.

## Отчёт и оптимизация

Показывать таблицу «этап — длительность — результат», общее время задачи и
непокрытые интервалы. `show` считает объединение интервалов и непокрытое время;
вложенные и параллельные этапы **нельзя суммировать** как общее время задачи.
Отрицательный результат не доказывает отсутствие пробела при неверных часах.
Незавершённый журнал не считать итоговым. Публиковать итоги после finish.

Журналы `source_guard` и `ui_session` дают детализацию отдельных запусков;
`profile_runs.py --project <project> --last 20` читает их отдельно. Общий журнал
задачи связывает анализ, код, запуски и отчёт; повторный учёт этих запусков
исключать. Сравнивать одинаковые сценарии и условия, показывать накладные
расходы защиты/снимков и не объявлять ускорение всей задачи по одному шагу.

Длительность процесса и календарный интервал включают ожидания и не равны
«чистому времени Codex» или времени генерации токенов. claude_time.py и
claude_stages.py читают только транскрипты Claude и не измеряют работу Codex.


## Использование замеров для улучшения навыка

Для повторяемой задачи start принимает scenario, environment, dataset, revision.
Анализ и правила принятия улучшений — `knowledge/self-improvement.md`.
`tools/workflow/analyze_timing.py` сохраняет неудачные попытки, пробелы, отдельные
и вложенные длительности. `tools/workflow/learning.py` сравнивает только одинаковые
сценарии/окружения/данные и формирует решение для рассмотрения, без автопубликации.
