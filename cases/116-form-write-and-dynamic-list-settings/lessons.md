# Запись методом формы и раздельные настройки списка

Стандартная команда записи показала служебный тост; метод формы Записать()
сохранил объект без него. Проверены отдельный EPF-пробник и настоящие формы.
Метод сохраняет стандартные проверки и обработчики записи. Закрывать форму
после команды записи только при успешном результате.

У справочника есть WriteAndClose, но перенос этого исключения в форму
проводимого документа остановил загрузку XML. Набор стандартных команд
проверять по главному реквизиту и целевой платформе. Для документа проверены
Write, Post, PostAndClose; проведение методом формы получает структуру с
РежимЗаписиДокумента.Проведение. РежимПроведения не задавать принудительно:
в пробе сохранён автоматический режим формы.

Для крестика проверены асинхронные Да Нет Отмена: Да записывает, Нет отвергает
изменение, Отмена оставляет форму и введённые данные. При ЗавершениеРаботы
оставлен штатный путь: в этом событии нельзя открывать окна и вызывать сервер.
Глобального документированного отключения тостов и управления их длительностью
в этих пробах не получено. Встроенные сторонние формы не охватывались.

ПолучитьНастройки() компоновщика возвращает совмещённые фиксированные,
основные и пользовательские настройки. Обратная загрузка в основные настройки
дублировала фиксированный отбор владельца: «Пересекаются элементы отбора».
Менять только порядок списка, Настройки.Порядок и элемент типа
ПорядокКомпоновкиДанных в ПользовательскиеНастройки.Элементы, сохраняя отборы.
Правка проверена реальной сортировкой по названию и последующим перемещением;
проверка сохранённых номеров через COM сама по себе этого не доказывает.

TestManager: ТестируемоеПолеФормы.Открыть() эмулирует кнопку открытия поля;
ТестируемаяТаблицаФормы.УстановитьПорядок принимает видимый заголовок колонки,
повторный вызов меняет направление. Сочетания клавиш этими методами не проверены.

Обратная выгрузка опускает ModifiesSavedData=false и другие значения по
умолчанию, упорядочивает свойства и права. Не ослаблять защиту выпуска:
остановить выпуск, разобрать конкретные различия, сохранить копию исходника,
принять только проверенные XML и повторить сверку. В проекте сверено 1001
файл без расхождений; тексты BSL и порядок дочерних элементов UI не изменились.
