# Веб-публикация демо-базы с внешней обработкой: модуль 8.5 роняет httpd в СЛК, публикация отдельным Apache 8.3.27

**Объекты.** Копия рабочей базы КАО АЗОТ (1С:ТОИР КОРП 3.0.8.1 + расширение ФРЕГАТ, платформа 8.3.27) с демо-настройками.
Внешняя обработка «АЗОТ Анализ потерь материальных потоков» зарегистрирована в «Дополнительных обработках» БСП.
Публикация на сервере, где уже работает Apache 2.2.14 со службой и публикациями других баз (EamDev/UatDev/UatPse) на веб-модуле 8.5.1.

**Что пошло не так.**
1. Публикация базы через модуль 8.5.1 (как у соседних публикаций): при входе пользователя процесс httpd падал с `0xC0000005`, в веб-клиенте — «Сеанс отсутствует или удален». В журнале приложений сбойный модуль — `v8_….licenceaddin-x86_64.dll` 3.0.32: компонента лицензирования СЛК, защита ТОИР. С модулем 8.3.27, той же версии, что база, веб-клиент работает: сообщения «Сервер СЛК не запущен» есть, но без падения.
2. В копии рабочей базы выключена функциональная опция `ИспользоватьДополнительныеОтчетыИОбработки` — зарегистрированная обработка нигде не видна.
3. Снимки окна тестового клиента по фильтру `TESTCLIENT` захватывали окно ДРУГОГО проекта: на сервере параллельно шли его тесты.
4. Сеанс без повышенных прав: правка `httpd.conf` в Program Files — «Permission denied». Службой Apache пользователь управлять может, конфигурацией — нет.
5. `Allow from 127.0.0.1 ::1` — Apache 2.2 под Windows: «The specified IP address is invalid».

**Результат.**
- Отдельный экземпляр Apache — служба `Apache2.2-Azot`, порт 8083, модуль 8.3.27. Рабочий Apache не трогается, перезапуск не нужен.
- Файлы публикации готовит `публикация.py`, службу ставит `publish_Azot.cmd`. Его запускает администратор и выбирает доступ: только с сервера или для всех; для всех — с правилом брандмауэра. Снимает публикацию `unpublish_Azot.cmd`.
- Та же конфигурация запущена в консоли и проверена в браузере:
  - вход;
  - «Оборудование и нормативы → Дополнительные обработки → Анализ потерь»;
  - граф, все шесть видов;
  - мост «Применить в модель».

**Confidence:** HIGH для падения на 8.5.1 и работы на 8.3.27 (проверено в консольном httpd, в песочнице и вне её). Службой проверка пройдёт у пользователя.
