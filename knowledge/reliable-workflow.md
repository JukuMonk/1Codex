# Защита выпуска и управляемые UI-проверки

Переносимые модули находятся в `tools/workflow`. Для файловой тестовой базы
подготовлен [проектный CLI](project-runner.md). Он связывает библиотеку
с явными настройками проекта; остальные среды требуют своего адаптера.
Подключения, учётные данные, версию платформы, загрузку, резервное копирование
и разрешения на рабочую базу задаёт проект. Использовать вместе с
[правилами проверки](validation.md), [тестированием](testing.md) и
[обязательным замером этапов](task-timing.md).

## Выпуск

`source_guard.py`: project_lock → FrozenRun → lint → backup → load/UpdateDBCfg
→ CheckModules → COM/UI → обратная выгрузка/сверка → временный CF → publish.
Проектный адаптер выполняет эти операции, библиотека защищает вход и журнал.
Каждую длительную операцию оборачивать в run.stage. Исходники и защищённую
копию проверять перед/после этапа; изменение останавливает выпуск. Копия
независима от живого дерева, нормализация BOM/CRLF применяется только к ней.
Windows read lease запрещает запись/удаление файлов копии до закрытия.

Не принимать отличие XML как форматирование по одному факту успешной
загрузки. cosmetic_equivalent допускает лишь консервативные преобразования;
порядок узлов, значения свойств и смысл BSL не игнорируются. Принятую
каноническую выгрузку сохранять отдельно, живое дерево автоматически не
переписывать. При гонке публикации сохранять предыдущий CF. В finally
закрывать leases даже при ошибке записи журнала или нехватке места.

`resource_lock.py`: base_lease(project, database) исключает конкурентные
операции над одной базой у сотрудничающих инструментов этого проекта.
Блокировка по нормализованному пути, не по отображаемому имени. Она не
запрещает стороннему клиенту 1С подключение. Для SQL нужен отдельный
нормализованный идентификатор подключения в адаптере; путь не заменяет его.
Держать lease вокруг реальных операций базы. Родительский цикл не должен
удерживать её, пока ждёт дочерний UI-процесс, которому нужна та же база.

## UI и снимки

`ui_session.py`: ProjectLock брать до сборки и запуска UI. RunArtifacts
создаёт уникальный каталог и manifest; текущий результат публикуется атомарно.
Закрывать только принадлежащие запуску процессы через Popen handles.
Не закрывать все клиенты базы ради нового снимка. Имена кадров проверять
safe_frame_name. Полный функциональный прогон и отдельный кадр отчёта имеют
разные режимы и артефакты: кадр не выдавать за повторную приёмку.

`ui_dsl.py` строит команды без запуска 1С. Точные имена кнопок и колонок брать
из выгрузки и дерева формы. Добавление/копирование требует имени команды;
редактирование выбора активирует нужную колонку. Проверять текущую строку
и видимый порядок после перемещений. Метки расширенного поиска зависят от
версии платформы и формы: подтвердить их в целевой базе. Диагностика контекста
текстовая; снимок добавлять явно там, где он доказывает результат.

`tools/workflow/reference/manager.bsl` внутри tools/workflow — модуль формы внешнего
TestManager из УП, а не собранная EPF. Перенести обработчики в менеджер проекта,
проверить события формы и собрать его штатным способом. Он реализует DSL,
отдельный progress, полный стек менеджера и проверку ошибки приложения.
Новый DSL не подключать к старому менеджеру без обновления обеих сторон.
Обычный поиск отсутствующего ErrorInfo может неявно ждать секунды: читать
ограниченное дерево активного окна, не вызывать поиск по отсутствующим полям
после каждого шага. Проверять ошибку до/после действий и ожиданий.

`ui_error_log.py`: перед запуском зафиксировать размеры локальных .lgp;
при ошибке читать только новый ограниченный хвост, выбирать запись по
признаку ошибки и маскировать известные секреты. В отчёт переносить текст
ошибки, не весь журнал. Это адаптер конкретного формата .lgp, **не** чтение
SQL-журнала/.lgd. Краткий ErrorInfo и стек менеджера не выдавать за исходный
стек приложения. Кнопку отправки отчёта автоматически не нажимать.

## Проверенные границы

Источник: УП, коммит 01eb054, Windows, Python 3.12, платформа 8.5.1.1529,
файловая песочница. Пройдены положительный UI, отсутствующая точная кнопка,
намеренная ошибка приложения с исходными строками стека, конкуренция процессов,
дочерний UI под защитой цикла и полный выпуск песочницы (74,12 с, 991 файл,
0 расхождений). SQL и другие версии этим прогоном не подтверждены.
При переносе модулей повторяются автономные тесты; новую интеграцию с базой
проверять в песочнице проекта. Дополнительная защита имеет измеримую стоимость.

Тесты без 1С: `python -m unittest discover -s tools/workflow/tests -v`.
Проектные генераторы УП, данные и настройки развёртывания в библиотеку не входят.
