# Уроки (HIGH — проверено в платформе 8.5.1, ФРЕГАТ EAM, 26.10.2026)

1. **«Начало сеанса с информационной базой запрещено. Программа заблокирована для обновления на новую версию»**
   на COM и в клиенте, `/CРазрешитьРаботуПользователей /UC` без кода не помогает. Это блокировка БСП
   `СоединенияИБ.УстановитьБлокировкуСоединений` с кодом по умолчанию **`КодРазрешения`**: подключиться
   `File="...";UC=КодРазрешения;` и вызвать `СоединенияИБ.РазрешитьРаботуПользователей()`. Код
   `ПакетноеОбновлениеКонфигурацииИБ` не подошёл. Перед этим проверить: не нужно ли базе обновление
   (`ОбновлениеИнформационнойБазы.НеобходимоОбновлениеИнформационнойБазы()`), иначе клиент снова заблокирует.
2. **Догрузить проект в тестовую базу без потери демо-данных:** `platform.py load` пересоздаёт базу. Вместо него —
   копия проекта → `1cedtcli export` → `/LoadConfigFromFiles` + `/UpdateDBCfg` в ту же базу → обновление ИБ через COM
   (функции `paths/step/designer/stop_clients` из `tools/platform.py`).
3. **Снимок формы «как на телефоне» без мобильного клиента:** форма с двумя назначениями в узком окне тонкого клиента.
   Окно тестируемого клиента (`ui`) — процесс **1cv8.exe**, а `GetWindowText` у окон 1С из чужого процесса
   **пустой**: искать окно по PID процесса (WMI: путь базы и `ENTERPRISE` в командной строке, без `TESTMANAGER`),
   не по заголовку. Скрипт держит окно `MoveWindow(…, 760, 1180)`, сценарий `ui` снимает с `"ui_printwindow": true`
   (копия экрана пропускает перекрытое окно). Кадр — обрезка области формы правее панели разделов и рамка телефона;
   в подписи честно: «узкое окно тонкого клиента».
4. **Шаг `значение` не читает надпись (Decoration)** — «нет элемента … (Тестируемое поле формы)»; итог экрана
   проверять через COM (`call Модуль.Функция`).
5. **check_bsl case 015 на многострочной `НСтр("ru = '…\n|…'")`** — проверка принимает строки с `|` за текст запроса
   и ругается на одиночную кавычку; многострочные сообщения собирать массивом строк + `СтрСоединить(…, Символы.ПС)`.
6. **COM «Библиотека не зарегистрирована» после обновления приложения Claude Desktop (EAM, 26.10.2026).** Коннектор
   V85 был зарегистрирован только на пользователя (HKCU, `register_com.py`), V83 — ещё и в HKLM. После того как
   приложение стало упакованным (служебные пути `AppData\Local\Claude-Data`), его дочерние процессы перестали видеть
   библиотеку типов из HKCU: `pythoncom.LoadRegTypeLib('{88511CA9-…}')` → TYPE_E_LIBNOTREGISTERED, V83 из HKLM
   грузится. Повторный `register_com.py` из сессии не помогает (запись, видимо, уходит в вид пакета). Помогает
   регистрация в HKLM: `regsvr32 /s "<bin 8.5>\comcntr.dll"` от администратора (`Start-Process -Verb RunAs`,
   пользователь подтверждает UAC). Общие интерфейсы V83/V85 после этого продолжают работать оба.
