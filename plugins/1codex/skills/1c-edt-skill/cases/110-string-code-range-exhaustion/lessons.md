# Длина метаданных и состояние нумерации — разные проверки

В песочнице воспроизведено «Значение "9999" поля "Код" не уникально».
Длина 4 → 9 и ОбновитьНумерациюОбъектов не исправили генерацию после старого
максимального 9999. Fixed не помог и добавлял пробелы к старым кодам;
его применение отменено, исходные коды песочницы восстановлены.

Приведение числовых кодов к одной ширине с ведущими нулями дало новые коды
000010000 и 000010001. Явный дубль отклонён, повторный план пуст, после отката
сохранены 2039 исходных ссылок и кодов. Семь COM-проверок пройдены.

Не отключать уникальность как окончательное исправление. Если её уже отключали,
сначала аудит дублей. Корректировать коды без удаления/объединения объектов;
нечисловые коды, внешние классификаторы и обмены разбирать отдельно. Этот кейс
не разрешает массовые правки рабочей базы. Проверка плана на копии, резерв и
окно обслуживания обязательны перед применением к рабочим данным.

Проверять старые и новые записи, следующий код, повторный запуск и rollback.
Не утверждать универсальность для всех версий/типов кодов по одному прогону.
Механизм ведущих нулей: [документация 1С](https://its.1c.ru/db/content/metod8dev/src/developers/platform/metod/applied/i8102745.htm).
