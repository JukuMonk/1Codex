# Уроки

**Частичная загрузка (`LoadConfigFromFiles -listFile`) работает объектами верхнего уровня, и корень — тоже объект.**
`Configuration.xml` без корневых `Ext/**` стирает модули приложения и сеанса, командный интерфейс, справку и
`ParentConfigurations` (поддержку) — у типовой на поддержке это ещё и поставочный `.cf` (~280 МБ у УАТ). Новые
объекты без корня не загружаются («нельзя добавлять объекты метаданных без загрузки родительского объекта»).
Поэтому корень в пакете — целиком, а пакет с новыми объектами тяжёлый. (Без поддержки то же для своей
конфигурации — case 078.)

**Пакет проверять до отправки, а не у заказчика.** Копия эталона ← пакет → выгрузка → сравнение со «стало» по
содержимому: допустимо только `ConfigDumpInfo.xml`. Так нашлось стирание корневых `Ext` — по глазам пакет выглядел
верным, а COM-проверка данных его бы пропустила.

**Выгрузка EDT в XML может упасть разово** («дефект в файлах проекта»), в том числе если в это время в репозиторий
проекта коммитят. Повтор проходит. Опасно не падение, а продолжение: скрипт, который после неудачной выгрузки идёт
дальше, проверяет СТАРУЮ конфигурацию — проверять по выводу, что база действительно перегружена.

Источник: МВМ, `инструменты/дельта_обновление.py` (пакеты 20261008_2209, 20261009_2037 — проверены на копии
эталона, совпали с ПСИ кроме `ConfigDumpInfo.xml`).
