# Совершенствование по измерениям

Каждая задача сохраняет этапы по `task-timing.md`. Для сравнения повторяемых
сценариев при start задавать `--scenario`, `--environment`, `--dataset` и
`--revision`. Это короткие неперсональные идентификаторы версии платформы,
Python, ОС и входа, без паролей, команд и бизнес-данных.

```
python tools/workflow/analyze_timing.py --project <project> --output <analysis.json>
python tools/workflow/learning.py --project <project> --baseline <old> --candidate <new> --hypothesis "Причина ожидаемого улучшения" --output <decision.json>
```

Анализ объединяет интервалы, вычитает вложенные этапы, сохраняет неудачные
попытки и непокрытое время. Параллельные этапы даже после вычитания детей могут
пересекаться: их сумму нельзя называть общим временем. Незаконченные журналы и
явный перевод часов исключаются из сравнения. Неизвестные поля окружения не
объединяются в одну сопоставимую выборку.

Цикл улучшения:
1. По журналам выбрать дорогой или часто неуспешный этап.
2. Записать гипотезу, метрику и условия, при которых изменение отвергается.
3. Снять исходные результаты на одинаковых данных, затем внести проверяемую правку.
4. Повторить сценарий в том же окружении. Для первичного сравнения нужно хотя бы
   пять успешных измерений каждой версии; сохранить также все ошибки.
5. Сопоставить медиану, разброс, долю ошибок и объём проверки. Рост ошибок имеет
   приоритет над ускорением. Пять повторов не доказывают статистическую значимость.
6. Зафиксировать результат и регрессионный тест. Только затем предлагать выпуск.

learning.py выдаёт insufficient_samples, quality_regression, improvement_candidate,
slower_review_tradeoff или no_material_change. Порог 5% — ориентир для анализа,
не автоматическое разрешение менять правила. Ускорение одной функции нельзя
переносить на всю задачу. Дополнительные проверки могут обоснованно увеличить
длительность. Скрипт не переписывает навык и не публикует обновления.

Разброс выводится как минимум, максимум и MAD — медиана абсолютных отклонений
от медианы. Пример воспроизводимого сравнения с прежним `edt_lib.py`:

```
python tests/designer/benchmark_bsl.py --baseline-file <old-edt_lib.py> --output <new-empty-dir> --samples 10
```

Этот сценарий чередует версии, запускает новый Python-процесс и 600 BSL-проверок,
сравнивает хеш диагностики. Он не измеряет время ответа модели или работу 1С.

Журнал задачи отдельно показывает анализ, реализацию, тестирование, исправления
и отчёт. Это календарное время с ожиданиями, не стоимость токенов и не «чистое
время модели». Расход токенов без данных среды неизвестен.
