# Симптом → причина → правило

CF мог перестать соответствовать проверке: разные этапы читали меняющееся
живое дерево. Повторный UI мог занять ту же базу, а отчёт взять старый снимок.
Сумма внутренних этапов выпуска скрывала подготовку и контроль входа.

Независимая запечатанная копия, проверки манифестов на границах, OS locks,
отдельные каталоги запусков и атомарная публикация устраняют эти классы гонок
у сотрудничающих инструментов. Finally освобождает ресурсы даже при disk full.
Защиту базы не держать в родителе во время дочернего UI — иначе взаимная блокировка.

Подробный контракт и модули: [надёжный цикл](../../knowledge/reliable-workflow.md).
Учёт подготовки, проверок, повторов и ожиданий: [замеры](../../knowledge/task-timing.md).
Не складывать вложенные этапы. Пример after выполняет только lint; он не
выдаёт разрешение и не реализует развёртывание в рабочую базу.

Подтверждено: положительный и отрицательные UI, исходный стек приложения,
конкуренция и освобождение после аварии, дочерний UI в цикле, выпуск песочницы
74,12 с / 991 файл / 0 расхождений. Эти 74,12 с — время конкретного выпуска,
не время всей доработки и не время модели. Перенесённая библиотека дополнительно
проверяется автономно на временных файлах; тесты не обращаются к 1С.
