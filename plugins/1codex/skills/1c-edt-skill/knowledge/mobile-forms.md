# Мобильные формы

Проверено на мобильном клиенте 8.3 (телефон) и тонком клиенте одной и той
же формой. Пример — `examples/mobile/mobile-form/`, эталон —
`reference/DataProcessors/мвмМоиРейсы/`.

## 1. Что должно быть включено

1. У КОРНЯ конфигурации `<usePurposes>MobileDevice</usePurposes>` рядом с
   `PersonalComputer` (Configuration.mdo). Без этого форма с назначением
   `MobileDevice` создаётся, лежит в дереве и НЕ открывается: в EDT редактор
   пуст, в платформе её не выбрать (case 005). После включения EDT проверяет
   ВСЕ формы конфигурации на пригодность мобильному клиенту — предупреждений
   много, это норма.
2. У формы в `.mdo` владельца — `<usePurposes>MobileDevice</usePurposes>` и,
   если её же смотрят на компьютере, `PersonalComputer`. ОДНА форма с двумя
   назначениями — рабочий вариант: экран проверяют в тонком клиенте, не
   доставая телефон; страницы закладками работают одинаково (case 006).
3. Роль с правом `MobileClient` у конфигурации (`knowledge/roles.md`).

## 2. Что не работает или работает иначе (HIGH)

| Что | Как на самом деле | Case |
|---|---|---|
| смахивание ПО СТРОКЕ таблицы | у платформы нет: `Swipe` в модели форм только у группы СТРАНИЦ (`FormPagesRepresentation.Swipe`); действия над строкой — контекстное меню (долгое нажатие) или кнопка на странице | 030 |
| командная панель таблицы | телефон рисует «More actions» на своём языке; ставить `commandBarLocation None` | 041 |
| булева колонка таблицы | показывается словом «No»; в мобильных списках булевы колонки не держать | 041 |
| строки поиска/состояния над таблицей | три полосы в две строки — `searchStringLocation/viewStatusLocation/searchControlLocation None`; сами спутники в XML оставить (без них EDT таблицу не рисует) | 004, 041 |
| кнопки в верхней панели | мобильный клиент прячет их в «ещё»; главное действие — `UsualButton` во всю ширину на странице (`edt_lib.page_button`) | 041 |
| страницы `Swipe` | листаются пальцем, закладок нет; на компьютере между ними не перейти → `TabsOnTop` работает везде и надписи страниц видны | 030 |
| длинный текст | надпись (`Decoration`) с текстом через `Заголовок` переносится; поле обрезает | 041 |
| пустые поля | занимают место молча — прятать `Видимость = НЕ ПустаяСтрока(...)` | 041 |
| поле HTML | работает (карта рейса SVG в HTML), явные `width/height` обязательны | 022 |

## 3. Как строить экран

- Логика в общем модуле («что показать и что разрешено нажать» решает одна
  функция, форма раскладывает ответ) — форма перечитывается по таймеру
  (`ПодключитьОбработчикОжидания("ПоТаймеру", 60)` в `ПриОткрытии`).
- Таблица значений общего модуля кладётся в реквизит формы
  `ЗначениеВРеквизитФормы`; колонки реквизита — надмножество колонок таблицы.
- Выбор из списка — `ПоказатьВыборИзМеню` с `ОписаниеОповещения`;
  подтверждение — `ПоказатьВопрос`; результат действия — `ПоказатьПредупреждение`
  или оповещение в углу `ПоказатьОповещениеПользователя` (в чате окно «ОК» на
  каждую реплику невыносимо).
- Подложка карты для телефона — ужатая копия (2000 px, 64 цвета, ~300 КБ)
  двоичным макетом; данные в `data:`-URI без переводов строк (`Base64Строка`
  их вставляет).

## 4. Отладка «форма пустая в EDT»

Лесенка проб (`reference/generators/проба_мобильной_формы.py`): временная
обработка с формами, каждая на один элемент отличается от предыдущей;
открывать по очереди в EDT. Так найдены (case 006): `numberQualifiers` у
числового реквизита (истинная причина пустого листа), `saveWindowSettings`,
номера колонок. Отвергнутые гипотезы: «форму с одним мобильным назначением EDT
не рисует», «таблица значений в мобильной форме не отображается» — обе
оказались следствием числа без квалификаторов. Если EDT держится за прежнюю
версию объекта — пересоздать объект с новыми uuid (`--обработку-заново`),
но это крайняя мера: новый объект требует полного обновления базы (case 020).
