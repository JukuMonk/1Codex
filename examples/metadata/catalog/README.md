# Справочник — ПримерСправочник

**Что демонстрирует.** Плоский справочник с реквизитами четырёх типов
(ссылка на перечисление с проверкой заполнения, число, булево, строка
неограниченной длины), табличной частью `Точки` (X, Y — Число(15,3)),
двумя формами и ссылками на них из .mdo (`defaultObjectForm`,
`defaultListForm` — после `choiceMode`, case 039). HIGH.

**Обязательные файлы.**

```
ПримерСправочник/ПримерСправочник.mdo
ПримерСправочник/Forms/ФормаЭлемента/Form.form     ← копия examples/forms/simple-item-form
ПримерСправочник/Forms/ФормаЭлемента/Module.bsl
ПримерСправочник/Forms/ФормаСписка/Form.form       ← копия examples/forms/list-form
```

Регистрация: `<catalogs>Catalog.ПримерСправочник</catalogs>`.

**Что можно менять.** Состав реквизитов и ТЧ — через `edt_lib.attribute`
(порядок тегов внутри реквизита фиксирован: `minValue → maxValue →
fillChecking → fillValue → fullTextSearch → dataHistory`; у реквизита ТЧ
`fillValue` нет — case 025). Длина строки ≤ 1024 или 0 (case 024).
`codeLength`/`descriptionLength`; `hierarchical` — только если ТЗ
действительно говорит об иерархии групп (case 029), тогда все запросы к
справочнику обязаны отсекать `ЭтоГруппа` (case 017). Имена реквизитов — не
ключевые слова запросов (case 016).

Меняя реквизит, менять и формы: путь данных `Объект.Имя` в Form.form
должен вести к существующему реквизиту (`check_form` это сверяет по .mdo).

**Что согласовано.** uuid — `stable_uid('Catalog/ПримерСправочник')` и по
реквизитам; `<forms>` в .mdo ↔ папки `Forms/<Имя>/Form.form`; ссылки на
справочник в регистре, документе, обработке, отчётах — `CatalogRef.ПримерСправочник`.

**Похожее.** `knowledge/metadata.md` §4, §9; `forms/simple-item-form`,
`forms/list-form`; `reference/Catalogs/мвмУзлыКарты` (боевой, с формами),
`мвмТипыУзлов` (много перечислений-цветов).
