# 1c-edt-skill

Набор знаний, рабочих примеров и 89 разобранных кейсов, снятых с реальных
проектов (ТЛЭиУА 1.1.36 / МВМ на 8.3.24, ФРЕГАТ EAM на 8.5.1, EDT). Набор общий
для всех 1С-проектов и пополняется из каждого — правила в `CLAUDE.md`, раздел
«Пополнение набора». Главный принцип:
**WORKING EXAMPLE > ABSTRACT KNOWLEDGE > MODEL MEMORY** — файл, работающий в
базе, важнее правила, правило важнее памяти модели.

## Как применять

1. Прочитать `CLAUDE.md` этой папки — алгоритм из 10 шагов и запреты.
2. Найти задачу в `index/patterns.md` («хочу сделать X») или тему в
   `index/topics.md`; ошибку — по симптому в `knowledge/common-errors.md`,
   затем кейс в `cases/NNN-*/lessons.md` (`before/` → `after/`).
3. Копировать структуру из `examples/` и `reference/`, не собирать XML из
   головы; значения тегов `.mdo` брать из модели EDT (`grep` по типовой).
4. Перед укладкой в проект прогнать `tools/check_project.py <корень EDT>
   --prefix <префикс>` и `tools/check_bsl.py <модуль> [--common] [--hier …]`
   до нуля ошибок; каждое сообщение ссылается на кейс.
5. В отчёте назвать уровень проверки по `knowledge/validation.md` §5; не
   утверждать «работает» без прогона в базе.
6. Новая ошибка → новый кейс в `cases/` тем же коммитом и строка в
   `knowledge/common-errors.md`, `index/cases.md`.

Новый проект доработок — `knowledge/new-project.md` и `tools/new_project.py`
(справочник метаданных, CLAUDE.md проекта, git и резервная копия).

Проверка в платформе без человека — `knowledge/testing.md` и `tools/platform.py`
(загрузка в пустую базу, обновление ИБ, COM: отчёты и запросы, снимки форм).

## Где что

- `knowledge/` — 17 тем: структура проекта, метаданные, формы, мобильные
  формы, BSL (в §9 — производительность по замеру), СКД, подсистемы, роли,
  поле HTML, uuid, развёртывание, генераторы, проверка, каталог ошибок,
  проверка в платформе, новый проект, работа без EDT (выгрузка Конфигуратора).
- `examples/` — образцы метаданных, форм, мобильной формы, отчётов, BSL.
- `cases/` — 89 кейсов: task / before / after / lessons.
- `reference/` — боевые файлы и генераторы; `tools/` — сборка и проверки.
