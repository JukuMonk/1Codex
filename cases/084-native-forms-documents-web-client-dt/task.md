# Без EDT: документы и нативные формы на построителе, ошибки только веб-клиента, .dt для показа на чужом сервере

**Проект и платформа.** ФРЕГАТ ПУЛЬС (`C:\gold\ZHDRM`), своя конфигурация без БСП, 8.3.27.2342, совместимость 8.3.21,
файловые базы, веб-публикация Apache 2.2; итерации 13–14 (15–17.10.2026).

**Задача.** Подсистема «Производство»: документы «Маршрутный лист» (из 1С:ERP, две табличные части) и «Сменное задание»;
форма мастера «Сменные задания» — сначала страницей поля HTML, затем по требованию заказчика «полностью в 1С, но
красиво»; формы документов «шапка в две колонки, табличная часть выше, комментарий — вкладкой»; демо-база для показа
на ДРУГОМ сервере (без датчиков и ERP) выгрузкой .dt.

**Что пошло не так.**
1. В наборе документ числился MEDIUM («до первой загрузки и сверки»), своей формы документа не было ни одной.
2. Построитель форм (`designer_lib.Form`) не задаёт ни шрифтов, ни цветов, ни условного оформления — нативная форма
   выходила «серой таблицей».
3. Заказчик открыл форму мастера в веб-клиенте — ошибка при нажатии; в тонком клиенте, на снимках форм и в проверках
   через COM её не было: `XMLСтрока` на клиенте в веб-клиенте не определена.
4. `/CheckModules`: «Функция <<?>>ИмяПользователя()» — своя функция с именем глобального метода; ранее — вызов `Ln(…)`
   (натурального логарифма с таким именем в языке нет).
5. Выгруженная .dt через час после выгрузки показывала у всех 83 станков «Не настроено»: телеметрия была заложена
   вперёд (до конца следующих суток), а регистр состояний досчитался только до момента выгрузки.
6. Проверка .dt разворачиванием: `CREATEINFOBASE` списком аргументов — код 1; `/RestoreIB` с `/N"Администратор"` в пустую
   базу — «Пользователь ИБ не идентифицирован».
7. Инструменты: `sed -i` в Git Bash перевёл CRLF-файлы в LF (diff «изменён весь файл»); скрипт правки с `'''` внутри
   heredoc — «unexpected EOF» разбора команды.

**Результат.** Два документа и три формы (обработка + два документа) собраны генератором, загружены, `/CheckModules`
чисто, сверка обратной выгрузки 0 расхождений из 300 файлов; формы проверены снимками клиента; ошибка веб-клиента
найдена по журналу регистрации через COM и исправлена; .dt (15 МБ) выгружена и проверена разворачиванием в чистую базу.

**Confidence:** HIGH (загрузка, сверка, снимки, COM; веб-клиент — по журналу регистрации реального сеанса заказчика).
