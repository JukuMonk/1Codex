# BSL: то, что компилятор пропускает, а платформа роняет в бою

Все правила — из падений в живой базе (номера — `cases/`). Проверка перед
укладкой: `python tools/check_bsl.py Module.bsl`.

## 1. Директивы компиляции (модуль формы)

- Процедура модуля управляемой формы БЕЗ директивы компилируется СЕРВЕРНОЙ.
  Клиентских методов там нет: `ОткрытьФорму`, `ПоказатьВопрос`,
  `ПоказатьПредупреждение`, `ПодключитьОбработчикОжидания`,
  `ПоказатьВыборИзМеню`… падают «Процедура или функция с указанным именем не
  определена» — и только при нажатии кнопки (case 011).
- Вставлять код между директивой и объявлением нельзя: функция теряет
  `&НаСервереБезКонтекста`, становится серверной С контекстом, и вызов из
  функции без контекста падает при первом открытии. Якорь вставки — директива
  ВМЕСТЕ с объявлением (case 012).
- `&НаКлиентеНаСервере` при серверном вызове платформа не нашла
  («Процедура … не определена»); рабочее решение — две процедуры с одним
  телом, `&НаСервере` и `&НаКлиенте` (case 033, MEDIUM: причина не доказана,
  лечение проверено).
- Схема формы: `&НаКлиенте Команда(Команда)` → `&НаСервере КомандаНаСервере()`
  → серверная работа; `&НаСервереБезКонтекста` для функций без формы (им
  доступно имя `Объект` как обычная переменная).
- В `&НаСервере`-процедуре доступны `Элементы`, `Объект`, реквизиты формы;
  условное оформление — там же (`examples/bsl/conditional-appearance.bsl`).

## 2. Имена

- В модуле формы `Параметры`, `Объект`, `Элементы`, `ЭтаФорма`, `ЭтотОбъект`,
  `Команды` — свойства формы, только чтение: `Параметры = Новый Структура(…)`
  падает «Поле объекта недоступно для записи». Ловили дважды (case 010).
  Исключение — процедуры `БезКонтекста`.
- Реквизит метаданных не должен быть ключевым словом запроса (`По`, `С`
  как «По»…): `Записи.По КАК По` → «Ожидается имя» (case 016).
- Локальные переменные не называть именами глобальных структур (в JS
  ловили с `N`; в BSL — имена модулей и глобальных функций).
- Имя функции модуля не должно совпадать с глобальным методом платформы:
  `Функция Состояние(…)` серверного модуля падала при старте ТОЛСТОГО
  клиента «уже определена (Состояние)» — там серверные модули компилируются
  в процессе клиента; в тонком и на сервере работало. Вылезает при
  профилировании (профилировщик EDT запускает толстый клиент). Список —
  `tools/edt_lib.GLOBAL_METHODS` (case 047).
- Имя команды формы — имя процедуры: `Прервать`, `Продолжить`, `Возврат`,
  `Выполнить`, `Перейти` дают «Ожидается имя процедуры», EDT молчит (case 057).
- Реквизит формы занимает имя и у локальных переменных процедур С
  контекстом: `Парк = ТСДляПакета()` при реквизите `Парк` — «Нельзя изменять
  поле, содержащее объект данных формы». Новый реквизит — сначала `grep`
  присваиваний (case 059).

## 3. Свойства и методы, которые пишутся не так, как кажется

- «Число + Строка» не склеивает: тип результата задаёт ЛЕВЫЙ операнд,
  `Номер + ". "` падает «Преобразование значения к типу Число» на первой
  строке с данными. Число слева — `Строка()` или `Формат(…, "ЧГ=")`;
  `"…" + Число` безопасно (case 058, `tools/check_bsl.py`).

| Неправильно | Правильно | Ошибка платформы | Case |
|---|---|---|---|
| `Объект.ОбменДаннымиЗагрузка = Истина` | `Объект.ОбменДанными.Загрузка = Истина` | Поле объекта не обнаружено (ОбменДаннымиЗагрузка) | 014 |
| `Справочники.X.ПустаяСсылка` | `Справочники.X.ПустаяСсылка()` | Поле объекта не обнаружено (ПустаяСсылка) | 032 |
| `Ссылка.ТабличнаяЧасть` | запрос `Документ.X.ТЧ` или `ПолучитьОбъект()` | не поддерживается | (CLAUDE.md) |
| `РегистрыСведений.X.Получить(Отбор) = Неопределено` | запрос `ВЫБРАТЬ ПЕРВЫЕ 1 … ГДЕ ключ = &…` | Получить возвращает структуру ВСЕГДА, с пустыми ресурсами | 018 |
| `Перечисления.X.Запрет` (имя выдумано) | имя значения из `.mdo` | Поле объекта не обнаружено (Запрет) | (CLAUDE.md) |

Правило: свой же рабочий код копировать надёжнее, чем писать по памяти —
правильный образец `ОбменДанными.Загрузка` стоял строкой ниже ошибочного.

## 4. Тексты запросов

- Запрос живёт внутри строкового литерала: кавычка внутри — только
  удвоенная, пустая строка — четыре кавычки `<> """"`. Одна забытая пара
  роняет сборку всего пакета «Строка, не закрывающаяся кавычкой» (case 015).
  Проще не сравнивать со строкой в запросе, а отсеять пустое в коде.
- Иерархический справочник: `И НЕ X.ЭтоГруппа` в каждом запросе — у группы
  реквизиты NULL, и `Окр(NULL * 1000)` роняет всё «Преобразование значения к
  типу Число» (case 017). Групп в базе разработчика может не быть годами.
  У ПЛОСКОГО справочника поля `ЭтоГруппа` нет — «Поле не обнаружено».
- Агрегат по строке неограниченной длины запрещён: `МАКСИМУМ(ВЫРАЗИТЬ(Поле
  КАК СТРОКА(150)))` (case 031).
- Пакет запросов: результат читается по позиции `Результаты[N]` — вставка
  запроса в середину молча сдвигает всё ниже; держать индексы поимённо и
  сверять поле с N-м запросом. Выбрасывая запрос, считать разделители: два
  `;` подряд — пустой запрос, «Ожидается выражение ВЫБРАТЬ».
- `ВЫБРАТЬ РАЗРЕШЕННЫЕ` — при ролях с RLS понадобится.
- Запрос в цикле EDT считает ошибкой — собирать соответствия одним запросом.

- Псевдоним таблицы или подзапроса не должен совпадать с именем ТЧ любого
  объекта запроса: `… КАК Тарировка` при ТЧ «Тарировка» — «Неоднозначное
  поле "Тарировка.Ссылка"» в бою (case 062).

## 5. Записи и объекты

- Запись типового объекта ради одного своего реквизита — в режиме
  `ОбменДанными.Загрузка = Истина`, иначе типовая проверка заполнения не даст
  записать.
- Необязательный расчёт внутри сборки данных — только в `Попытка`: украшение
  не имеет права ронять данные.
- Пропускаемые при записи объекты (`Продолжить`) класть в список оставшихся,
  иначе следующий шаг «пометить лишнее» удалит их как отсутствующие.
- Аргументы с единицами читать из СИНОНИМА реквизита (мм/т/м), а не гадать.

- «Записать всё, что прислали» — переписать весь справочник: `ПолучитьОбъект()`
  и `Записать()` на каждый объект пакета, половина времени — типовые проверки
  при записи. Текущие значения читать одним запросом на пакет, писать только
  то, что отличается, числа сравнивать с точностью реквизита (case 051).
  «Только изменённые» касается ВСЕГО, что запись пишет и пересчитывает:
  зоны, регистры-производные (case 053). Разностная запись регистра —
  набор с отбором по измерению: `Записать(Истина)` заменяет строки ровно
  этого значения, пустой набор снимает прежние.
- Соответствие, сложенное по ссылке, читать `Соответствие[Ссылка]`; помощник
  с `Строка(Ключ)` для ссылки берёт ПРЕДСТАВЛЕНИЕ и ничего не находит —
  молча (case 053). `Строка(Ссылка)` в цикле — ещё и запрос представления.

## 6. Вставка в типовой модуль (генераторы)

`tools/edt_lib.insert_into_procedure(текст, имя, строка, в_начало)`:

- в начало — за ЦЕЛЫМ переводом строки объявления, иначе остаётся одиночный
  LF (case 026);
- в конец — перед `КонецПроцедуры`; последний оператор типовой процедуры
  может стоять без `;` (перед `КонецПроцедуры` так можно), а после него наш
  вызов требует `;` — ставить самим (case 026);
- идемпотентность по подстроке; область своего кода `#Область Мвм…` в конце
  модуля переписывается целиком при каждой сборке.

## 7. Общие модули

- Помощники (`ЧислоИлиНоль`) — свои в каждом модуле: функция из чужого
  модуля, вызванная без префикса, падает при первом выполнении (case 013).
- Серверный модуль с `serverCall` зовётся с клиента; без `serverCall` — нет.
- Повторное использование возвращаемых значений: `returnValuesReuse` —
  `DuringRequest` (на время вызова) или `DuringSession` (на время сеанса);
  других значений нет, придуманное `DuringCall` EDT принял МОЛЧА и выгрузил
  модуль без кэша (case 048). Функция такого модуля — без параметров,
  зависящих от вызова; сброс — `ОбновитьПовторноИспользуемыеЗначения()`.
- Экспортная функция «экран» возвращает структуру — форма только раскладывает
  (мобильная форма). Таблица значений → `ЗначениеВРеквизитФормы`.

## 8. Клиент

- Таймер: `ПодключитьОбработчикОжидания("Имя", 60)` в `ПриОткрытии`,
  `ОтключитьОбработчикОжидания` в `ПриЗакрытии`; минимальный интервал
  повторяющегося — 1 с; однократный отложенный — третий параметр `Истина`.
- Диалоги — через `ОписаниеОповещения("Продолжение", ЭтотОбъект, Параметры)`
  и экспортную процедуру-продолжение (`examples/bsl/open-form-with-callback.bsl`).
- Форму, открытую с оповещением, закрывать `Закрыть(Результат)` — результат
  придёт в продолжение.
- Долгий серверный вызов при открытом поле HTML — карта продолжает принимать
  клики; отключать опрос на время и включать в `Попытка`.

## 9. Производительность (HIGH, cases 049–053, 055)

Что дорого в 1С, решает замер, а не довод. Профилировщик EDT: цель
«Сервер» для серверного кода (клиентский профиль про него молчит);
экспорт `results_info.xml` — тики по 100 нс. Причину называть по данным:
«контуры по сотне вершин» было сочинено, запрос показал 4–10 (case 052).

- Перебор минимума по всем узлам — O(N²): на 930 узлах и 78 маршрутах
  13 млн итераций. Двоичная куча с ленивым удалением (case 049).
- Граф и параметры, не меняющиеся за вызов, — в модуль с
  `returnValuesReuse DuringSession`; функция без параметров, сброс при
  записи (cases 048, 049).
- Реквизит «по ссылке» в цикле — запрос в цикле: 11 179 чтений за одну
  операцию. Поле того же запроса (`ЕСТЬNULL(ВЫРАЗИТЬ(… КАК Справочник.X).Поле, 0)`),
  кэш на вызов, один серверный вызов на обновление экрана,
  `СсылкаСуществует` вместо `ПолучитьОбъект()` (case 050).
- Писать только изменённое — и объекты, и производные регистры (cases 051, 053).
- Геометрия «каждый с каждым» — после описывающих прямоугольников; цена
  растёт как объекты × зоны (case 052).
- Индексы — по сверке запросов с `.mdo` (case 055).
- Интерпретируемая строка BSL стоит порядка 10–30 мкс: 68 тыс. проверок
  «в рамке» — около двух секунд. Считать не только запросы, но и циклы.
